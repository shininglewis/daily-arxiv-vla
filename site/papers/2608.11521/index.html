Card 02 论文概述

论文概述

  • 论文研究 世界动作模型（WAMs） 中动作生成对预测未来表示的依赖问题，指出迭代式视频 rollout 会显著增加部署延迟（3.3× 至 9.6×）
  • 通过配对闭环干预协议分析未来 K/V 缓存是否必须随去噪步进演化，发现动作专家只需有意义且位置绑定的未来值，而无需完整的 rollout 轨迹
  • 提出 Rift（Rollout-free Imagination via Future Tokens） 方法，用学习到的 anticipation tokens 在单次骨干网络前向传播中构造完整未来 K/V 缓存，保留原始未来读取接口且无需部署期视频生成
Card 03 核心贡献

核心贡献

  • 提出配对闭环干预协议：记录动作无关的未来缓存，在固定键下遮蔽读取或编辑值，并以 EE-ADE 和成功率度量物理执行变化
  • 识别未来缓存的两个关键性质：移除未来读取或跨空间/时间重赋值会显著破坏执行（如掩蔽后成功率从 98.4% 降至 9.7%）；而单个固定 final-clean K/V 缓存几乎可保持执行（EE-ADE 仅 1.7–1.9 cm，成功率 97.9–98.2%）
  • 设计并验证无 rollout 的未来接口 Rift：一次 prefill 生成完整未来缓存，在 LIBERO 上达到 98.8% 成功率，接近 rollout 基线（98.4–98.6%），同时将延迟降至当前仅模型的 1.1×
  • 在 RoboTwin 2.0 上达到 92.9/92.6%（干净/随机化场景）成功率，为评估方法中最高
Card 04 方法描述

方法描述

  • Rift 基于 Fast-WAM-Joint 架构，以 m 个可学习 anticipation tokens（LIBERO 上 m=196，RoboTwin 2.0 上 m=240）替换 rollout 未来 tokens，每个 token 继承对应的时空索引
  • 一次 CachePrefill 将第一帧 tokens [f₀(o); E] 映射为所有层的未来位置 K/V 缓存，动作解码器通过原始未来读取接口消费该固定缓存
  • 训练采用双前向策略：视频流损失监督干净首帧视频预测；部署匹配的动作前向使用条件流匹配（conditional flow matching）对 anticipation 状态进行分布性监督，避免直接 L2 回归导致的未来平均化
  • 采用停止梯度的线性探针提供确定性未来隐变量读出，并可作为可选的 L2–FM 不一致性不确定性预警（不参与策略部署）
  • 动作损失仅在干净样本上计算，70% 训练后引入首帧潜在噪声扰动（概率 0.3、幅度 0.06）以匹配部署时观测噪声
Card 05 数据集与资源

数据集与资源

  • 使用 LIBERO 基准：40 个任务（Spatial/Object/Goal/Long 四个套件），每方法单 checkpoint、3 个评估种子、每种子 2,000 次试验
  • 使用 RoboTwin 2.0 基准：50 个双机械臂任务，干净与域随机化场景，每任务 100 次试验
  • 基础模型为 Wan2.2-5B Fast-WAM 骨干，训练预算：LIBERO 20k 步，RoboTwin 2.0 30k 步
  • 训练数据：LIBERO 全任务演示；RoboTwin 2.0 使用 2,500 个干净场景与 25,000 个随机化场景演示
  • 延迟测量在单张 A800 GPU 上进行，每动作块毫秒数
Card 06 评估与结果

评估与结果

  • 干预研究（全部 40 个 LIBERO 任务，2,000 配对试验）：掩蔽未来读取致 EE-ADE 11.8–20.4 cm、成功率降至 0.0–32.0%；空间置换/时间交换致成功率分别降至 65.2%/0.7%；final-clean K/V 重放仅产生 1.7–1.9 cm EE-ADE、成功率 97.9–98.2%
  • LIBERO 总体成功率：Rift 达 98.8%，优于 Fast-WAM（96.8%）和 PFD（97.3%），与 Fast-WAM-Joint（98.4%）、Fast-WAM-IDM（98.6%）、LingBot-VA（98.5%）同一水平
  • 部署延迟：Rift 每动作块 247.9 ms，较 rollout 方法降低 68.2–89.1%（Joint 780.2 ms、IDM 1081.2 ms、LingBot-VA 2270.3 ms）
  • RoboTwin 2.0：Rift 在干净/随机化场景分别达 92.9%/92.6%，超过 PFD（92.5/92.1）、LingBot-VA（92.4/91.4）、Fast-WAM（91.9/91.6）和 Fast-WAM-Joint（91.0/91.1）
