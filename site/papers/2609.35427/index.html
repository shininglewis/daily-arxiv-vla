LLMs are General Asynchronous Agents

2026-09-28 · 原文 · 翻译 · 2609.35427

论文提出 AsyncLLM：一个将大语言模型（LLM）智能体变为通用异步智能体的框架，允许用户或智能体自身定义具有重叠内存状态的推理协程（coroutines），无需任务特定微调。 要解决的问题：现代 LLM 智能体遵循"读取-思考-回复/调用工具"的顺序交互循环，但许多真实场景（语音助手、具身智能体、监控系统）需要在思考时持续接收新输入，现有多数方案为每个异步任务单独设计专用架构并进行昂贵训练。 研究目标：验证现代 LLM 是否能像通用工具使用者、少样本学习者一样，成为通用异步智能体，并在流式视频理解、电子游戏、系统监控等异构场景中无训练地泛化。

Card 03 核心贡献

核心贡献

  • 提出 AsyncLLM：一个在 async/await 编程模型下实现免训练异步 LLM 智能体的通用框架，将异步编程原语扩展到定义具有重叠内存状态的并行 LLM 推理协程。
  • 提出一种支持共享内存状态（attention KV caches、Gated Delta Network 循环状态）的并行 GPU 推理算法，使同一 LLM 的多个实例可并发运行并实时看到彼此的进度，适用于混合与多模态 LLM。
  • 基于同一系列 Qwen3.x VLM 无任务特定微调地构建了流式视频理解、电子游戏环境、系统监控三类异步智能体，验证框架的通用性。
  • 展示现代 LLM 能在同一推理循环中自行定义和修改协程，为未来"从环境描述自生成自适应智能体"提供初步证据。
Card 04 方法描述

方法描述

  • AsyncLLM 编程模型：基于 Python asyncio 标准库，用协程和同步原语（event、lock、queue）定义并发推理；每次前向传播将内存状态写入一个 CacheBlock，该块包含一段连续 token 的 attention KV 缓存与 GDN 循环状态。
  • Cache Views（缓存视图）：单次前向可同时"看到"多个任意顺序的 CacheBlock，数学上等价于顺序编码的单一 KV 缓存；多个协程并发更新彼此可见的块时，形成非顺序但 LLM 可理解的记忆状态。
  • 多缓存块推理算法：针对全注意力层，沿用 Rodionov et al. (2025) 的做法，仅旋转当前查询的 RoPE 位置，不重排历史 KV；针对 GDN/线性注意力，提出将块内多步更新打包为仿射变换 (Â, B̂) 矩阵，并按 O(N_blocks) 而非 O(N_tokens) 成本组合；针对多模态注意力（MRoPE），按时间维相对位置旋转查询并显式维护每块位置跨度。
  • 调度与推理引擎：基于 mini-SGLang 实现，包含前端 asyncio 接口、平衡批调度（避免快速反应协程被大背景请求阻塞）、以及基于 Paged Attention 的批量推理内核；采用 chunked prefill 提高交互性，并复用 Flash Linear Attention 处理 GDN。

Card 06 评估与结果

评估与结果

  • 单异步输入 sanity check：在 MATH-500-Sharded 与 ShardedVQA 上评估，AsyncLLM 智能体在文本澄清与图像修正两种模态下均能在推理中途对异步输入作出反应；视觉任务准确率下降稍快，原因是其平均所需推理步数较少。
  • 流式视频理解：AsyncLLM + Qwen3.5+ 在 SoccerNet (streaming) 与 ProactiveVideoQA (ω=0.5) 两个基准上均优于专门训练的 Mage-VL（如 SoccerNet TimVal 39.62 vs 27.87；ProactiveVideoQA ALL PAUC 0.541 vs 0.428），更大模型还给出更准确的描述。
  • 交互式视频游戏智能体：在 ViZDoom 上，AsyncLLM 智能体相比同模型顺序智能体可显著更快反应（更低的观察-动作前向步数延迟），同时保留推理带来的收益，但作者指出这只是验证基本能力而非 SOTA。
  • 系统监控智能体：在 DevOps-Gym 上，AsyncLLM 与顺序基线准确率相当（如 Q3.6-35B-A3B 下 55.88% vs 61.76%，协程并行将前向步数从 8452 降至 3837），但延迟显著降低。
  • 推理吞吐：1×H200 上 9B 模型 1 协程 106 tokens/s，8 协程达 552 tokens/s；ProactiveVideoQA 上视频流处理速率约 2.5–4.4 秒流/GPU 秒（纯视频）。
