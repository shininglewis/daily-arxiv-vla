Card 03 核心贡献

核心贡献

  • 提出 PyRUA-Lean 代码接口：在相同 GPT-6 Astra 规划器与相同基元下，将成功率从 63.1% 提升到 71.7%，在共同解决的任务实例上减少 49% 的 LLM 调用和 65% 的输入 token。
  • 在 RoboDojo 上取得领先结果：不使用任何 VLA 策略、演示或特权信息，平均成功率 51.6%（Score 58.2），比公开排行榜第一名高 19.4 个百分点，是同一 LLM 直接控制末端执行器的 2.3 倍，并在全部五个能力维度上均为最高。
  • 基于该框架训练开源规划器 PyRUA-Lean Coder v0.1-4B：仅用 45 个 LIBERO-PRO 实例做 GRPO 训练，在未见任务上成功率从 18.8% 提升到 44.1%，超过 Qwen3.5-27B 基座模型；在 RoboTwin 2.0 上从 14.0% 提升到 52.4%，并承诺开源权重。
  • 通过消融实验与 token 分解分析，验证了增益主要来自减少 LLM 调用次数，而非单纯缩短单次提示；并说明仅在工具调用中改成按需返回图像并不能复现收益。
Card 04 方法描述

方法描述

  • 机器人被暴露为 Python 对象 robo，其方法封装运动、夹爪、VLA 策略、移动底盘、感知等基元；智能体通过 python(code) 工具生成代码单元，运行时执行后回传反馈。
  • 反馈驱动的基元组合：单个代码单元可组合多个基元、检查中间结果、按结果分支或重试，还可自行计算几何量与定义辅助函数（如从世界坐标图计算放置目标高度、构造带保护的下降函数）。
  • 选择性观测与上下文管理：中间结果保留在持久化 Python 命名空间中而不进入对话；只有显式 print 输出和 robo.show 请求的图像才会在单元结束时一并返回，从而由代码决定哪些观测进入 LLM 上下文。
  • 执行模型：未捕获异常终止当前单元并回传 traceback，异常前已赋值的变量仍保留；任务成功后运行时会终止单元；外部看门狗以两小时为单回合上限。
  • RoboDojo 上的自建基元库：仅含运动、夹爪与感知基元（如 move_to、set_gripper、locate、segment、back_project、state、show），没有 pick/place/grasp 这类高层原语，抓取需由代码组合实现；SAM 3 是除 LLM 外唯一的学到的组件。
  • 训练方法：以 GRPO 微调 Qwen3.5-4B，仅以任务成功作为奖励，得到 PyRUA-Lean Coder v0.1-4B。

Card 06 评估与结果

评估与结果

  • 对比协议：固定规划器、基元与任务实例，仅改变接口（工具调用 vs. 代码执行），两个智能体均不使用跨回合记忆。
  • 主要指标：成功率、LLM 调用次数、累计输入 token、按标价估算的推理成本；效率指标在“两个智能体都成功”的实例上统计。
  • 成功率：整体从 63.1% 提升至 71.7%（+8.6 个百分点，约 14% 相对提升）；分项为 LIBERO-PRO +11.0、RoboTwin 2.0 +9.2、RoboCasa365 原子任务 +7.8、复合任务 +5.0；仅 PyRUA-Lean 解决的实例有 96 个，仅工具调用解决的仅 36 个。
  • 效率：共同解决实例上平均 LLM 调用从 17.0 降至 8.7，输入 token 从 788k 降至 276k，单回合成本从 $1.63 降至 $0.74；LIBERO-PRO 上达到基线最终成功率的 token 预算为 564k 对 3.18M。
  • RoboDojo：PyRUA-Lean 平均成功率 51.6%（Score 58.2），在 Generalization、Precision、Long-Horizon、Memory、Open 五个维度上均优于公开排行榜各维度最佳条目。
  • PyRUA-Lean Coder v0.1-4B：在未见任务与基准上成功率从 18.8% 提升到 44.1%，RoboTwin 2.0 上从 14.0% 提升到 52.4%，超过 Qwen3.5-27B 基座模型。
  • 消融与局限：去除 VLA 策略或操作指南后，PyRUA-Lean 仍保持更高成功率与更低 token 使用；在 RoboCasa365 原子任务上收益最小（含失败回合时两者输入 token 比约 1.1×、成本接近）；仅改成按需图像的工具调用基线成功率反而从 83.0% 降到 68.5%。
