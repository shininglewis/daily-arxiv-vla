DriveReferee: Geometric Safety Verdicts Need Not Be Learned for Driving World-Action Models

Card 03 核心贡献

核心贡献

  • 提出面向驾驶 WAM 的 verification decomposition，将 learned scene-state inference 与 analytic geometric verdict computation 分离，使已知安全规则可直接在预测状态上执行。
  • 提出 DriveReferee 框架，复用同一零参数 analytic referee：训练时在 GT maps 上做 preference distillation，部署时在 self-predicted maps 上做 alarm-gated candidate selection。
  • 通过 matched-budget comparisons 与 same-map learned replacement 控制实验，隔离“学习最终 verdict”的价值；发现学习 verdict 没有可测量收益，即使使用 66,385 个 evaluator-labeled 训练样本。
  • 在完整 NAVSIM navtest 上以单目视觉输入、无外部训练数据达到 92.02 PDMS / 91.56 EPDMS，并保持视频生成质量。
  • 显示增益不来自策略规模：在 4B Cosmos3-Edge 上同样将 PDMS 从 90.47 提升到 91.50。
Card 04 方法描述

方法描述

  • 问题设定：输入为 H+1 帧前视相机历史 I、导航命令 c、当前 ego 速度与全局朝向 s0；未来规划表示为 τ；readout 额外接收 ego pose history P。
  • 世界-动作策略 π_θ：基于 Cosmos3 联合生成未来视频和动作 token；冻结 reasoner tower，仅训练 generation tower；重复采样可产生多候选轨迹，无需额外 proposal network。
  • 感知 readout g_φ：从冻结视觉特征出发，采用 LSS/Simple-BEV 式 depth distribution + BEV lifting + ego-pose 对齐，预测静态可行驶区域图 M_drv 和 1+T_f 时间索引车辆占据图 M_veh；训练时冻结视觉 backbone，仅优化 φ。
  • Analytic referee R(τ,M)：零学习参数；先使用 LQR tracker + kinematic bicycle model 对离散 waypoints 做闭环运动学 rollout；在每步 ego footprint 的四个角点和中心查询；检查是否越出可行驶区域或进入车辆占据栅格；输出违规计数 n_dac, n_nc 与距离变换 clearance margins m_dac, m_nc，并聚合为 n(τ) 和 m(τ)。
  • 训练时偏好蒸馏：策略自采样 K_t 条轨迹，分为通过集合 P 与违规集合 V；保留两者均非空的场景；winner 为通过候选中 margin 最大者，loser 为违规候选中距专家轨迹最近者；使用 reference-free pairwise preference objective（flow-matching losses + logistic preference term）训练，仅 loser 选择用到专家轨迹。
  • 部署时门控选择：默认计划 bar τ 用预测 M_hat 评估；若 n(bar τ)>0 或 m(bar τ)≤Δ 则告警；再采样 K-1 个候选，在同一 M_hat 上按“违规数少、clearance 大、距默认计划近”排序；仅当违规数减少至少 δ_n 或同等违规数下 clearance 提升至少 Δ 时替换。
  • 关键设计：margin 在同一 predicted map 上做相对比较，而非绝对安全证书，以降低共享局部地图偏差的影响。
Card 05 数据集与资源

数据集与资源

  • 数据集：NAVSIM 的完整 navtest split，共 12,146 个场景；训练使用 navtrain；评估采用官方 one-stage 设置和非反应式 log-replay 交通智能体；PDMS 对应 NAVSIM v1，EPDMS 对应 NAVSIM v2。
  • 模型：主策略 Cosmos3-Nano，总参数量 16B，可训练 generation tower 8B，reasoner tower 冻结；对照 Cosmos3-Edge，总参数量 4B，可训练 generation tower 2B。
  • 感知 readout：训练时冻结视觉 backbone，仅训练 φ；使用栅格化特权标注；部署时预测 maps 与 GT maps 保持相同时空表示。
  • Same-map learned verifier 对照：4.15M 参数，使用 66,385 个 evaluator-labeled 训练候选。
  • 训练细节：偏好训练 850 steps、462 pairs、学习率 2e-5；偏好构造每场景 K_t=5 个自采样；视频 832×480 @ 2Hz，输入 4 历史帧加当前帧，预测 8 未来帧。
  • 部署参数：occupancy grid 0.4 m，clearance threshold Δ=0.4 m，compute-matched 比较用 K=2；operating point 在 held-out driving logs 上固定。

Card 06 评估与结果

评估与结果

  • 评估环境：完整 NAVSIM navtest（12,146 场景），scene-level paired comparisons，bootstrap 95% CI over 10,000 resamples；内部受控比较默认使用 EPDMS。
  • 主要指标：PDMS、EPDMS，并报告 NC、DAC、TTC、Comfort、EP 等子项。
  • 主结果：Ours (full, 16B) 达 92.02 PDMS / 91.56 EPDMS，NC 99.49、DAC 98.64、TTC 97.91、Comf 100.00、EP 84.99；仅蒸馏策略单次通过达 91.96 PDMS / 91.61 EPDMS。
  • 规模对照：Ours (full, 4B) 从 base 的 90.47 PDMS / 90.03 EPDMS 提升到 91.50 PDMS / 91.08 EPDMS，说明增益不依赖更大 backbone。
  • Referee fidelity：在 1,060 个 base policy 零分场景、每场景 5 条轨迹共 5,300 候选上，referee 与官方 evaluator 的 gate 决策一致率 91.0%（always-safe 基线 73.5%）；DAC precision 0.995/recall 0.631，collision precision 0.931/recall 0.792。
  • Map-source fidelity：同一 referee 在 GT map 与预测 map 上，默认计划的 m_dac 相关系数 0.895，平均绝对差 0.502 m。
  • 是否必须学习 verdict：matched-budget 下，最佳 learned verifiers 提升 EPDMS +0.23 和 +0.26，analytic referee 为 +0.30；same-map learned verifier 与 analytic referee 差异 -0.01 ΔEPDMS（95% CI [-0.15,+0.14]），83.4% 场景选同一计划，且平均 1.57 次采样/场景 vs analytic 1.35 次。
  • 监督 scaling：learned verifier 使用 5%/10%/25%/50%/100% 的 66,385 训练候选，分别提升 +0.00/+0.07/+0.17/+0.33/+0.27 ΔEPDMS；analytic referee 无 verdict-training label 即达 +0.35 ΔEPDMS。
  • 两种 placement：训练时偏好蒸馏给 undistilled base 带来 +0.92 ΔEPDMS（95% CI [+0.71,+1.13]）；部署时 gated selection 在 undistilled base 上带来 +0.30（95% CI [+0.18,+0.42]）；蒸馏后再加部署选择仅 +0.06 PDMS 和 -0.04 EPDMS，说明大部分收益已被蒸馏学习。
  • Ablations：去掉 pairwise term（β=0）后只有 +0.56 ΔEPDMS（完整 +0.92）；winner 若选“距专家最近”而非“safety margin 最大”，从 +0.92 降至 +0.63，配对差 +0.29（95% CI [+0.14,+0.45]）。
  • 视频生成质量：referee distillation 后 FVD 23.90→24.25，LPIPS 0.4166→0.4126，PSNR 18.75→18.92，无明显损失。
  • 部署干预：在 undistilled base policy 上，部署选择修复 53 个官方 hard safety-gate failure，引入 9 个；剩余错误主要来自预测地图与官方 evaluator 所用场景几何不一致。
