Card 03 核心贡献

核心贡献

  • 刻画（Characterisation）：在 7 个 VLA × 4 类 GPU 上对 7 类推理优化做配对测量，给出阶段级耗时与优化增益，包含“某平台上加速、另一平台上反而变慢”的案例。
  • 交互分析（Interactions）：揭示 CUDA graphs、编译、剪枝等前置优化会改变后续方法的增益，证明单独测量的百分比/毫秒节省不能直接复用。
  • 指南（Guidelines）：提出 VLA-Triage，一套基于测量的工作流，用于选择执行模式、做可行性筛选、并在部署延迟预算下验证方法组合。
  • 对 25 篇已发表 VLA 加速论文 做文献审计（附录 E），指出绝大多数未说明基线与被测方法的执行模式与注意力后端，导致结果无法被复现或迁移。
Card 04 方法描述

方法描述

  • 三阶段建模：视觉编码器 → 语言骨干 prefill → 动作生成（自回归解码 / 并行解码 / 扩散 / 流匹配四类动作头）。
  • 延迟预算模型：基于 LeRobot 异步调度器定义预算 B = Δ（单动作）或 B = A_r·Δ（异步分块，A_r=⌊(A-1)/2⌋），控制周期 Δ=50 ms（20 Hz），预算跨度 50–1200 ms。
  • Roofline 参照：对每个算子统计 FLOPs F_o 与访存字节 W_o，用实测峰值算力 C 与带宽 BW 计算参考时延 L_j = Σ max(F_o/C, W_o/BW)，并估计核外时间 I = T − K（CUPTI 记录核忙碌时间 K）。
  • 优化分类体系：按“移除工作 vs 替换内核”和“精度无损 vs 有精度风险”两维度分类；再区分 execution-preserving（主要去掉 CPU 发射）与 execution-altering（改变 GPU 核与张量形状），用于判断 eager 测量是否仍可复用。
  • 收益分解恒等式：g = σ(1 − 1/s)，用阶段占比 σ 与该阶段加速比 s 解释测得变化，并分析前置优化如何改变 σ 或 s。
  • 复用假设检验：对比 *percentage reuse*（T_reuse = T₁T₂/T₀）与 *millisecond reuse*（T_reuse = T₁ −(T₀−T₂)）相对实测组合时延 T₁₂ 的偏差，以 5.3%（实测最大基线漂移）为显著性阈值。
Card 05 数据集与资源

数据集与资源

  • 不训练模型，全部使用开源预训练 VLA 权重做推理测量。
  • 7 个 VLA：OpenVLA（Llama-2 7B，自回归 7 token）、OpenVLA-OFT（并行解码 + MLP）、LLaVA-VLA（Vicuna 7B，自回归 37 token）、CogACT（DiT + 10 步 DDIM + CFG）、π0.5（Gemma 2B + flow，10 步）、GR00T N1.7（Qwen3-VL 2B + DiT flow，4 步）、SmolVLA（SmolVLM2 0.5B + flow，10 步）；视觉 token 数 128–576，prefill token 149–712，kernel 数 2.7k–60k。
  • 4 类 GPU 平台：数据中心 H100、云端 A10G、消费级 RTX 4090、嵌入式 Jetson Thor。
  • 7 类优化：CUDA graphs、torch.compile（reduce-overhead / max-autotune）、融合注意力（FlashAttention-2 / SDPA）、batching、减少去噪步数、视觉 token 剪枝（FastV 等）、量化（int8/int4 权重、FP8、NVFP4、int8 计算）。
  • 量化实现库包括 CUTLASS、Marlin、GemLite、FlashInfer 等，每平台选取误差在最小值 1.25 倍内的最快实现。
  • 计时协议：绑定空闲 CPU 核、预热、每组至少 200 次推理取中位数，重复任务间中位差异 CUDA graphs 下 0.2%、eager 下 1.4%。
Card 06 评估与结果

评估与结果

  • 评估指标：端到端推理时延 T、相对延迟预算 B 的达标情况、核忙碌时间占比、核外（CPU 发射）时间占比、kernel 数量、加速比与预算决策正确性。
  • 非均匀增益：编译 + CUDA graphs 使 GR00T 在 H100 上更快、在 Thor 上更慢；CogACT int8 权重在 A10G 上更快、在 H100 上更慢。
  • 基线选择陷阱：FastV 50% 剪枝相对未融合注意力在 H100 上为 OpenVLA-OFT 节省 21.4%，相对 FlashAttention-2 仅节省 6.9%，因为选择器需读注意力权重而被迫使用慢核。
  • 核外时间与编译：H100 上 Llama-2-7B 解码 token 在 graphs 下耗时 9.6 ms，权重读取参考仅 3.7 ms；max-autotune 编译把 kernel 数降 1.9–2.8 倍、单 token 降至 5.7 ms。
  • 组合交互（Case 1，graphs→剪枝）：实测相对 percentage reuse 偏差在 −23% 到 +1% 之间，核时项与核外项偏差约 1 ms 内并可相互抵消；LLaVA-VLA 因解码 cache 改变需单独在 graphs 下测量。
  • 组合交互（Case 2，编译→剪枝/减步）：84 个编译+剪枝配置中 8 个超出 5.3%（最大 19%）；流程模型 32 个比较中 29 个 高于 percentage reuse 预测，最高 +227%（SmolVLA 在 RTX 4090：预测 17.4 ms vs 实测 56.9 ms）；CogACT 在 A10G 上剪枝收益从 eager 的 74.2 ms 降到编译后的 33.5 ms。
  • 组合交互（Case 3，剪枝→量化）：194 个编译剪枝-量化配置中 52 个超阈值，最大 49%；剪枝既改变量化覆盖阶段的占比 σ，也改变量化核的加速比 s。
  • 预算决策翻转：CogACT + 75% 剪枝在 A10G max-autotune 下，按毫秒复用假设为 23.3 ms（达标），实测 64.1 ms（超出 50 ms 预算）；int4 + 75% 剪枝按百分比假设为 48.5 ms（达标），实测 59.3 ms（超标）。
  • 跨平台迁移性：14 个“移除工作”类比较无一从加速变为变慢，而 21 个“替换内核”类比较中有 6 个发生方向反转（PyTorch 版本对齐后为 3/13）。
  • VLA-Triage 实例：OpenVLA-OFT 在 Thor 上预算 150 ms，扣除预处理与 5% 余量后剩 135.4 ms；编译后 152.6 ms 不达标，剪掉 50% 视觉 token 后降至 97.6 ms 达标，无需再叠加量化；CogACT 在 A10G 上扣除开销后仅剩 40.5 ms，最快配置 87.5% 剪枝 + int8 仍需 46.4 ms，说明需放宽控制周期。
