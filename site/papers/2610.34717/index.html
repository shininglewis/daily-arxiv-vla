Card 03 核心贡献

核心贡献

  • 构建 VLA-HWBench：覆盖 18 个开源 VLA 模型、19 个参考配置、四类动作生成方式和两种架构不同的边缘平台。
  • 提出 七阶段调用拆解：将一次推理分为 CPU 预处理、主机到设备拷贝、视觉编码、语言模型 prefill、动作生成、后处理和残余开销，并在阶段边界同步计时。
  • 在同一模型上系统比较推理优化：torch.compile、专用后端 TensorRT/FlashRT 和低精度 FP8/NVFP4，并将加速效果归因到具体阶段。
  • 给出三条核心洞察：延迟主要由动作生成迭代次数决定而非参数量；内核融合加 4-bit 权重收益最大但覆盖有限；优化后剩余时间受内存带宽、软件内核和主机 CPU 共同限制。
  • 为边缘 VLA 模型、推理软件和硬件设计提出方向：减少动作生成迭代、扩展内核融合与低比特执行、优先提升内存带宽和主机 CPU 性能。
Card 04 方法描述

方法描述

  • 将单次推理延迟建模为 T = ΣT₀…T₆，并用 T₄ ≈ N·t 表示动作生成时间随迭代次数 N 增长。
  • 采用阶段级归因：在每个阶段边界进行设备同步，检查各阶段时间之和是否等于端到端延迟，并利用 CUDA graph 内核顺序拆分融合阶段。
  • 使用 roofline 模型判断 GPU 阶段受计算、内存带宽还是软件实现限制，并结合 PyTorch profiler 统计算子形状、数值格式和内核类型。
  • 参考配置关闭可选优化，使用各模型自身 LIBERO 评测入口和固定权重；优化实验在 π0.5 与 GR00T N1.7 上逐项启用编译、专用后端和低精度。
  • 选择两个主机架构不同的平台：Arm 主机的 Jetson 与 x86 主机的 AMD，以分离主机、GPU 和内存带宽的影响。
Card 05 数据集与资源

数据集与资源

  • 使用 LIBERO-10 的真实观测作为统一输入：两张 256×256 相机图像、机器人状态和语言指令；另用同一 episode 的 24 帧检查输入内容对延迟的影响。
  • 评估 18 个开放 VLA 模型，形成 19 个参考配置；加载参数量约 0.45B–7.99B，包括 π0.5（4.14B）、GR00T N1.7（3.14B）、OpenVLA-OFT（7.71B）、RIPT-VLA（7.99B） 等。
  • 硬件平台为 NVIDIA Jetson AGX Thor T5000 和 AMD Ryzen AI Max+ PRO 395，两者均为 CPU/GPU 共享内存的边缘平台。
  • 软件栈包括 LeRobot 0.6.1、作者原始代码、FlashRT、TensorRT，以及 CUDA 13.2/PyTorch 2.11 和 ROCm 7.2/PyTorch 2.14。
  • 本文是推理基准，不训练模型，未报告训练 GPU/TPU 资源；资源消耗主要是两个边缘平台上的推理测量。
Card 06 评估与结果

评估与结果

  • 评估以 LIBERO-10 控制器 20 Hz 为实时性参照，即每 50 ms 执行一个动作，模型需满足 T/H < 50 ms 才能跟上控制频率。
  • 主要指标包括端到端延迟 T、每个动作的推理时间 T/H、各阶段占比、优化加速比 T₀/T、roofline 利用率以及低精度动作与 FP16 动作的余弦相似度。
  • 在 Jetson 上延迟范围为 77 ms–6.3 s（82×），在 AMD 平台上为 114 ms–17.9 s（157×）；仅 10/19 个 Jetson 配置和 9/19 个 AMD 配置满足 20 Hz 控制需求。
  • 动作生成是 Jetson 上 14/19 个配置的最大阶段，占调用时间的 42%–99%；参数量的对数拟合仅解释 9%（Jetson）和 15%（AMD）的延迟方差。
  • 延迟主要跟随动作生成迭代次数：流匹配用少量步骤生成长动作块可跟上控制，而逐 token 解码和推理链明显更慢；例如 VLA-0 的 208 个 token 占其调用时间 99%。
  • π0.5 在 Jetson 上经编译、专用后端和低精度分别加速 2.5×、1.8×、1.6×，总计 7.2×，从 318 ms 降至 44 ms；GR00T N1.7 总加速 2.6×，从 119 ms 降至 46 ms。
  • 内核融合加 4-bit 权重相对 torch.compile 再快 2.6–2.9×，但仅支持这两个模型且仅在 Jetson 上可用；AMD 平台只有编译优化，平台差距从 2.0–2.5× 扩大到 5.7–7.8×。
  • 优化会重新分配时间：π0.5 的视觉编码占比从 33% 降至 13%，prefill 从 14% 升至 34%；GR00T N1.7 的 CPU 预处理从 12% 升至 39%。
  • 优化后没有单一瓶颈：Jetson 上少 token 的去噪阶段受内存带宽限制，视觉编码和 prefill 受未融合内核及低精度支持限制，CPU 预处理受串行 Python 和线程唤醒开销限制。
  • 低精度保持较好动作一致性：FP8 的余弦相似度不低于 0.998，NVFP4 不低于 0.93；但编译可能改变动作并翻转夹爪指令。
