Card 03 核心贡献

核心贡献

  • 提出一种新的 模型感知场景复杂度刻画 方法：利用驾驶场景的时间连续性以及模型预测不确定性，通过时间帧之间的视觉变化和决策偏差来表示复杂度，并将其编码为场景感知 token。
  • 设计轻量的 预算条件层路由机制（Budget-Conditioned Layer Routing）：先用 budget query 决定激活参数比例，再用 routing query 在参数预算约束下选择最优层组合，整个流程端到端优化。
  • 在 Bench2Drive 闭环基准上取得优异结果：适配 SOTA 模型后，推理计算开销降低 53.5%，驾驶能力与语言能力下降可以忽略。
  • 验证了框架的可迁移性：同样可接入使用不同骨干模型的 ORION，并带来 47.4% 的 TFLOPs 降幅。
Card 04 方法描述

方法描述

  • 基础模型：以 SimLingo 为宿主，骨干为 InternVL2-1B（InternViT-300M 视觉编码器 + Qwen2-0.5B-Instruct 语言模型），适配后记为 SimLingo+SA。
  • 模型结构划分：LLM 被切分为 L_pre = 4 个前缀层与 L_sub = 20 个可路由层；只有前缀层之后的部分层会根据场景被动态激活或跳过。
  • 场景复杂度刻画：

- *场景时间偏差*：对视觉 token 做均值池化得到全局场景表示，用 EMA 维护历史表示，并通过多头交叉注意力建模时序演化，再用 MLP 融合生成场景偏差 token。

- *决策偏差*：对齐前两帧预测的路径与速度航点（自车运动补偿 + 线性插值），计算相邻帧偏差，经 Conv1D + 平均池化 + MLP 编码为路径偏差 token 和速度偏差 token。

  • 输入扩展：在原始 prompt 中额外拼接 5 个特殊 token：3 个场景感知 token（e_s、e_pw、e_sw）与 2 个专用查询（budget query q_b、layer routing query q_lr）。
  • 预算调度：在前缀层中部取出 q_b 的隐状态，经调度器输出离散预算动作 a，并换算为预算 b，再用正弦嵌入编码替换原 q_b token。
  • 层路由：在前缀层末尾，路由调度器结合 q_lr 与预算编码生成各子层 logits，经 Gumbel-Softmax top-k 采样得到二值掩码 M，未选中的层通过残差连接直接旁路。
  • 两阶段训练：

- *Stage 1*：SFT 初始化，预算从均匀分布随机采样，联合优化航点 Smooth-L1 损失、语言自回归损失，并加入 多样性损失 与 平衡损失 两个正则项（前缀层用 LoRA 微调）。

- *Stage 2*：冻结路由调度器，用 GRPO 强化微调预算调度策略，奖励同时权衡驾驶质量提升与预算节省，并引入 anchor loss 防止参数漂移。

Card 05 数据集与资源

数据集与资源

  • 评估基准：Bench2Drive（基于 CARLA 仿真器，含 220 条 150 米多样化路线）。
  • 语言能力评测：DriveLM-hard VQA（4,355 条测试样本）与 Driving Commentary（4,678 条样本），指标为 SPICE。
  • 训练数据：沿用 SimLingo 提供的数据集，联合优化驾驶与语言任务。
  • 模型规模：骨干 InternVL2-1B（InternViT-300M + Qwen2-0.5B）；新增辅助模块仅约 14M 参数。
  • 训练资源：2 块 NVIDIA RTX 4090；Stage 1 学习率 3e-5、batch size 6、约 90k 步；Stage 2 学习率 1e-5、batch size 4、约 40k 步。
  • 推理测速：在 RTX 4090 上测试每决策延迟与峰值显存。
Card 06 评估与结果

评估与结果

  • 评估环境：Bench2Drive 闭环仿真 + 语言 VQA/评论任务，统一在相同设置下测量 FLOPs、延迟与显存。
  • 主要指标：Driving Score（DS）、Success Rate（SR）、Efficiency、Comfortness、TFLOPs、Latency、Memory、SPICE。
  • 计算开销：SimLingo+SA 将 LLM TFLOPs 从 0.59 降至 0.27（-53.5%），延迟从 410.79 ms 降至 214.01 ms（-47.9%），峰值显存 2.03 → 2.01 GB。
  • 闭环性能：SimLingo+SA 取得 DS 84.87、SR 65.45%，相比原始 SimLingo（85.07 / 67.27%）仅下降 0.2% 和 1.82%，但 Efficiency（266.19）与 Comfortness（54.36）反超原模型。
  • 语言能力：全预算下 VQA 54.91（原 56.77）、Commentary 35.37（原 38.04），下降幅度有限，且在各预算设置下均优于 InternVL2-2B。
  • 与高效基线对比：DriveMoE 虽关闭语言输出，延迟仍达 319.54 ms、显存 14.85 GB；AutoVLA fast-thinking 延迟高达 1322.85 ms。
  • 消融结论：移除速度偏差或路径偏差 token 会使平均预算升至 71.89% / 66.70% 且性能下降；随机预算（60% 激活）效果劣于本文动态 45% 激活。
  • 泛化与安全：ORION+SA 降低 47.4% TFLOPs / 45.4% 延迟，性能仍优于 DriveMoE；失败路线分析显示，性能差距主要来自路线偏移而非碰撞等安全关键失效。
