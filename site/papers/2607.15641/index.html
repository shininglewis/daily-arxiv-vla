IMBench: A Benchmark for Intuitive Robotic Manipulation

2026-07-17 · 原文 · 翻译 · 2607.15641

IMBench 是一个用于评估直觉机器人操作（Intuitive Robotic Manipulation）能力的基准，包含 35 个操作任务，基于 robosuite 仿真环境构建，旨在测试模型能否将物理理解转化为可执行的动作。 现有基准存在明显割裂：物理推理基准止步于推断，操作基准只测策略执行而不要求显式推理。IMBench 填补了这一空缺，将感知、物理推理、动作生成和迭代执行整合为一个可系统测量的能力轴。 核心研究问题：模型能否从观测中推断任务相关的物理约束（理解）、生成可行的子目标序列（规划）、并在闭环仿真中执行动作（执行）？当前基础模型在这一整合能力上表现如何？

论文概述

Card 03 核心贡献

核心贡献

  • 提出了 IMBench——35 个 robosuite 操作任务，覆盖 7 个推理瓶颈类别（几何约束、动力学与轨迹预测、因果与间接动作、工具使用、隐状态与主动发现、反应式重规划、稳定性与平衡），系统性检验模型的物理理解到动作执行能力。
  • 发布了约 14K 条经过过滤的示范轨迹数据集，以及用于生成更多多样化场景的可扩展工具，支持可重复研究。
  • 形式化了理解–推断–行动（Understand–Infer–Act）三重认知分解，并提出三阶段 VLM 评测协议（约束理解 → 计划提议 → 闭环执行），结合策略 rollout，可量化测量从理解到执行的差距。
Card 04 方法描述

方法描述

  • 任务设计：35 个任务围绕"推理瓶颈"设计——每个任务包含一个必须从观测中推断的隐秘事实（不可行抓取、几何限制、动力学、因果链、隐状态、稳定性），成功执行需要精确的闭环物理控制。
  • 三阶段级联评估（IMBAgent）：Stage 1 通过 ReAct 提示提取物理约束；Stage 2 生成高层子目标序列；Stage 3 使用闭环 ReAct 框架，VLM 接收多视角图像、本体感觉和力/力矩信号，选择预定义动作原语并迭代反馈执行。
  • 端到端策略评估：对比 Diffusion Policy（DP，从零训练）、π₀.₅（零样本+微调） 和 GR00T N1.5（零样本+微调） 三类视觉运动策略，配置尽量贴近原始实现。
  • 数据过滤管线：示范轨迹经人工评分（1-5 分，保留 ≥4）、VLM 自动异常检测、人工终审三道过滤，确保示范质量。
Card 05 数据集与资源

数据集与资源

  • IMBench 基准：35 个任务，7 个类别 + 2 个杂项任务（mirror-pick-place、keyboard-typing）。
  • 数据集规模：约 14K 条过滤后轨迹；策略训练使用每任务 200 条人工演示轨迹。
  • 仿真环境：基于 robosuite，Gymnasium 风格接口，观测包括 2-4 个同步 RGB 视图、本体感觉、夹爪状态、腕部力/力矩；动作空间为 6-DoF 末端执行器增量 + 夹爪命令（单臂和双臂）。
  • 硬件：Franka 机器人（平行夹爪 + 吸盘），不支持灵巧手、移动平台或人形机器人。
  • 人工数据收集：遥操作 + 脚本化 oracle 策略（遥操作不可行的任务），并使用 VR 对比评估数据质量。
Card 06 评估与结果

评估与结果

  • VLM 高层推理（Q1、Q2）：评测 GPT-5.5、GPT-5.4-mini、Gemma-4、Claude Haiku-4.5、Claude Sonnet-4.6 五个模型。Stage 1 约束理解最佳为 Sonnet 4.6（74.5%） 和 GPT-5.5（74.1%）；Stage 2 计划正确性最佳为 GPT-5.5（69.5%）；P7 稳定性任务为最弱类别（37-80%）。
  • 闭环执行（Q3）：仅测 GPT-5.5（16 个任务，成本约 $1800）。IMBAgent 平均成功率仅 11.3%，仅 domino-single（100%）、domino-select 和 mirror-pick-place 有非零成功率；带特权物体位姿（IMBAgent-obj）提升至 18.8%。所有需精确对齐、时序、工具使用、隐状态或平衡的任务为 0%。
  • 端到端策略：零样本 VLA 性能极低（≤0.02）；微调后 Diffusion Policy 整体最佳（平均 0.24），在 mirror-pick-place、domino-select、occluder-push、slip-recovery 上表现最好；π₀.₅ 微调仅在 balance-medium（0.71）和 balance-hard 上成功。cup-inversion、shape-stack、packing、mass-sort、cracker-box 变体等任务所有策略均无法解决。
  • OOD 泛化：改变任务核心物理因子后性能显著下降，例如 balance-medium 从 0.71 降至 0.12，keyboard-typing 从 0.32 降至 0.04，表明策略依赖记忆模式而非鲁棒物理理解。
