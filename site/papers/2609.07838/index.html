Card 02 论文概述

论文概述

  • 本文提出 ComVLA（Communication-aware VLA） 框架，面向6G连网机器人场景，解决VLA模型分布式推理中无线链路带宽受限的问题
  • 核心思路是利用自然语言指令作为语义先验，在边缘侧筛选任务相关的视觉token，并将传输token预算与信道容量动态对齐，实现通信与推理的联合设计
  • 在 LIBERO 基准上仅传输 32/512 的 token，可降低 74% 推理计算量和 22% 推理延迟，平均任务成功率仅下降 1.5 个百分点
Card 03 核心贡献

核心贡献

  • 提出通信感知的VLA拆分推理范式：首次将VLA token剪枝建模为信息瓶颈（Information Bottleneck, IB）驱动的容量约束token选择问题，打通VLA推理与无线信道的协同设计面
  • 机制——语言引导的token选择与容量对齐预算：利用语言查询对视觉token做交叉注意力与硬投票评估任务相关性，并将每步可传输的token数量直接由信道SNR换算得到，实现实时自适应
  • 结果——静态与动态信道下性能稳健：仅传输32个token时，TX数据量降低16×，云端计算量降低3.8×，推理延迟降低22%，成功率损失仅1.5个百分点，并在Rayleigh/Rician衰落信道下保持稳定表现
  • 对CSI反馈延迟具有鲁棒性：即使SNR估计延迟达200 ms，成功率仅有微小下降，不需瞬时反馈
  • 验证INT8量化等带宽优化方案的可行性：在不影响任务性能的前提下可进一步减半传输数据量
Card 04 方法描述

方法描述

  • 系统采用边缘-云端拆分推理架构：边缘机器人提取视觉token并计算重要度，云端VLA骨干完成动作生成
  • 语义重要度估计：语言嵌入产生的查询（query）与全部视觉token做交叉注意力，生成任务感知表示，再通过点积相似度匹配回原始token，使用硬投票累计每个token的重要性分数
  • 信道自适应剪枝：根据香农容量公式计算每步的有效goodput，再结合 token特征维度与量化位数导出可传输token数上限 K^*，筛选重要性最高的 K^* 个token送入云端
  • 将token剪枝问题转化为受限于链路容量的选择问题（maximize 累积token语义相关度），在等长token假设下可通过排序快速求解
Card 05 数据集与资源

数据集与资源

  • 使用 LIBERO 机器人操作benchmark，包含 Spatial/Object/Goal/Long Horizon 四个套件，每套10个任务、每任务50个episode
  • 基础模型为 OpenVLA-OFT（已在LIBERO微调），视觉编码器为 SigLIP 与 DINOv2
  • 全量视觉token数为 512（两个相机视角合计），每个控制周期从边缘向云端传输的候选token数为16/32/48/64/128等，对应每步34～272 KB（INT8）
  • 实验全部在 NVIDIA H100 GPU 上运行
Card 06 评估与结果

评估与结果

  • 对比基线包括 OpenVLA-OFT（全量）、LightVLA、VLA-ADP（内容自适应token剪枝）、DeepJSCC 与 WITT（语义编码器）、Random Pruning（随机剪枝）
  • 主要评估指标为：任务成功率（Success Rate, %）、每步传输数据量（TX Data）、FLOPs 与推理延迟（compute latency）
  • 在 K=32 预算条件下，ComVLA 平均任务成功率达 95.4%，接近全量 OpenVLA-OFT 的96.9%；随机剪枝在该预算下仅55.7%，在Object套件上仅32.6%（ComVLA为97.0%）
  • ComVLA 将云端FLOPs由 8.8 TFLOPs 降至 2.3 TFLOPs（开环计算量减少约 3.8×）；云端推理延迟由54.8 ms降至42.7 ms，降低 22%
  • 在Rayleigh与Rician衰落模拟中ComVLA均优于随机剪枝：Object套件、Rician 5 dB SNR 时成功率为88.0%（随机剪枝仅56.2%）
  • 硬投票 vs. 软投票：硬投票（本文方法）平均领先1.7个百分点，尤其Long Horizon高出5.0个百分点
  • INT8量化可在几乎不损失性能的前提下将传输数据减半；INT4则造成显著性能退化（95.4%→67.3%）
