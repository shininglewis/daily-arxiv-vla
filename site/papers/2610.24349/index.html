Card 02 论文概述

论文概述

  • 论文针对 physical AI（物理 AI）中的 VLA、VA 与 WAM 三类策略模型，研究其单批次实时推理的延迟瓶颈问题。
  • 核心论点：“快 kernel 不等于快 pipeline”——延迟主要不来自单个 kernel 计算，而来自系统级开销，如数千次短 kernel 启动、算子边界间的中间数据搬运，以及跨决策的冗余重计算。
  • 通用图编译器（TensorRT、torch.compile、TVM）只能孤立优化单次调用，缺乏对跨调用状态语义和全局流水线结构的可见性，因此无法解决上述问题。
Card 03 核心贡献

核心贡献

  • 提出 FlashRT-PAI，一个以“模型–硬件流水线协同设计”为核心的推理引擎，联合决定 GEMM 分块、精度、生产者–消费者布局、融合方式与启动重叠。
  • 设计三种互补机制：深度 kernel 融合（消除算子间内存往返）、启动重叠（利用 CUDA PDL 减少剩余边界的等待）、执行契约与执行状态胶囊（跨决策状态复用与选择性刷新，支持快照/恢复/分支）。
  • 在受控的 π0.5/Thor 实验中，状态复用将决策延迟从 37.05 ms 降至 21.61 ms；恢复上下文并生成下一动作仅需 9.73 ms（重建需 21.48 ms），且复用与恢复的动作 bit-exact。
  • 支持对未修改的 PyTorch 模型进行即插即用加速：通过等价性（parity）与延迟双门控的 kernel 替换，保留宿主原有控制流与回退路径。
  • 多策略评估与开源影响：kernel 通过 Hugging Face Kernel Hub 分发，LeRobot 已采纳可选的 π0.5 kernel 集成。
Card 04 方法描述

方法描述

  • 深度 kernel 融合（§3.2）：利用部署特定事实（如已验证的量化尺度、下游 GEMM 的输入布局），手写生产者–消费者路径，将量化等操作折叠进生产者 kernel；π0.5 在 Thor 上的 FP8 decoder 层从 torch.compile+FP8 的 20 个 kernel 降至 12 个。
  • 启动重叠（§3.3）：在允许的边界标注后继 kernel 可提前开始与必须等待的位置，应用 CUDA Programmatic Dependent Launch (PDL)，让后继 kernel 在依赖仍被满足的前提下预取权重/做初始化。
  • 执行契约（§3.4）：显式记录阶段 DAG、各阶段更新速率（per-prompt / per-observation / per-decision）、具名缓冲区及其所有者与刷新规则，从而支持跨决策复用与选择性刷新。
  • 执行状态胶囊：将声明的持久状态以设备内内存拷贝方式进行 snapshot / restore / fork，会话管理器按更新节奏调度阶段重放。
  • 部署集成（§5）：每个可替换区域打包 PyTorch 参考实现与其 kernel，宿主仅在“与参考一致且端到端更快”时才采用替换。
Card 05 数据集与资源

数据集与资源

  • 数据集与基准：LIBERO 仿真（闭环任务成功率，主要报告 LIBERO-10）。
  • 评估模型：π0.5、LingBot-VA；背景分析还涉及 π0.7、FLUX 3 Action、GR00T N1.7、Cosmos、Motus。
  • 模型规模：π0.7 与 FLUX 3 Action 约 5–7B 参数；FLUX 3 Action 含冻结 Qwen3-VL-4B 编码器 + 7B DiT；π0.5 含 27 层 SigLIP、18 层 PaliGemma 前缀 LM、18 层 action expert。
  • 硬件平台：RTX 5090（工作站，6 个策略）与 Jetson AGX Thor（机器人端，4 个策略）。
  • 训练资源：本文为推理引擎工作，未涉及模型训练；原文未披露训练 GPU/TPU 规模。
Card 06 评估与结果

评估与结果

  • 对比基线：官方 eager 实现、torch.compile、可用的 TensorRT 部署；延迟与数值保真度采用固定/录制输入离线测量，任务成功率在 LIBERO 闭环评测。
  • 主要指标：单次决策延迟（ms）、相对加速比、动作/视频一致性（bit-exact 或等价性）、LIBERO 任务成功率。
  • 匹配 16-bit 精度下比官方编译路径快 1.3–3.7×；结合流水线协同设计与降精度，比官方 eager 实现快 3.38–12.66×。
  • LIBERO-10 上 4-bit π0.5 成功率达 94.04%（Thor） 与 93.32%（RTX 5090），优于实测官方 FP16 参考的 92.4%。
  • 延迟画像（Thor，官方 OpenPI eager，π0.5 单次决策 222.64 ms）：GEMM 之间的非矩阵 kernel 占 70.10 ms（31.49%），估计的 kernel 间空隙占 50.14 ms（22.52%）。
  • 参考延迟：Thor 上官方 π0.5 eager 222.64 ms、compiled 129.17 ms；RTX 5090 上 FLUX 3 Action 为 1.35 s。
