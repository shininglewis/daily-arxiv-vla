FastHarness: Experience-Driven Review Scheduling for Vision-Language-Action Policies

论文概述

  • 论文面向 智能体化机器人系统（agentic robot systems），研究如何在 视觉-语言-动作（VLA）策略 执行过程中调度大模型监督（review），以降低推理开销而不牺牲任务成功率。

Card 03 核心贡献

核心贡献

  • 提出 经验驱动的快路径（Experience-Driven Fast Path）：通过阶段识别与结果记忆，按阶段成功率动态拉长审查间隔，跳过冗余审查。
  • 提出配套的 错误恢复路径（Error Recovery Path）：检测到错误后逐 chunk 持续审查，先局部修复，必要时回退到本 episode 中已验证的 waypoint 目标。
  • 设计 恢复验证与恢复后接续机制：只有审查器确认故障解除才恢复正常调度，同时保留失败记录用于后续"错误邻近"触发。
  • 在策略完全冻结、不增加任何模型训练的前提下，同时实现效率提升与成功率提升，验证"自适应监督"是可行的工程路线。
  • 给出可复现的实现细节（匹配阈值、置信下界打分、间隔函数、触发优先级、控制步预算等）。
Card 04 方法描述

方法描述

  • 整体框架：在原有 GPT-as-Policy 执行骨架上加一个调度器，对每个新观测由 π_0.5 生成 action chunk，调度器决定是否送 GPT-6 Astra 审查。
  • 记忆表示：590 维特征 = 3 个 8×8 RGB 缩略图（576 维）+ 12 个关节角归一化 + 2 个夹爪指令；用 RMS 距离 做最近邻匹配，匹配阈值 0.06，歧义间隔 0.01，错误邻近半径 0.04，每阶段最多保留 128 个样本。
  • 保守可靠性打分：对每阶段的成功/失败计数计算 Wilson 型置信下界 r_s（z = 1.96），仅在样本量与连续成功足够时才允许放宽审查。
  • 审查间隔函数：I_s = 1 + ⌊(L-1)·r_s²·min(C, T_s/m)⌋，取 L=20、m=2、C=6，冷启动或错误后连续成功不足 c_min=3 时强制 I_s = 1（每 chunk 必审）。
  • 触发优先级（取首个满足条件）：强制审查模式 → episode 开始 → 恢复进行中 → 未知/歧义上下文 → 阶段切换 → 上次结果不确定 → 监控告警 → 错误邻近 → 控制步预算（120 步）→ 计划间隔 → 随机抽检（概率 0.03）。
  • 观测条件化执行：跳过审查时并不回放旧轨迹，而是在剩余预算内执行当前新提案的前缀，随后重新取观测与提案。
  • 恢复流程：局部修复（每次尝试最多 8 个 chunk）→ 连续两次失败后转向最近的已验证 waypoint → 验证返回目标后再独立评估原始故障 → 恢复正常调度。

Card 06 评估与结果

评估与结果

  • 评估协议：同一任务链内共享记忆、重复执行；效率对比 首个评估 episode 与 最后 5 个 episode 均值；成功率由环境原生 native_success 判定。
  • 主要指标：审查调用次数、review-skip rate（自动执行的 chunk 比例）、记录 token 数（输入+输出，缓存只计一次）、wall-clock 时间、原生任务成功率。
  • Token 效率：平均每任务降低 57.2%；等任务均值从 1.83M → 0.93M tokens/episode（Build tower 1.47→0.47M，Fold clothes 0.72→0.25M，Bottle disposal 1.64→0.58M，Classify objects 3.50→2.42M）。
  • 执行时间：等任务平均 episode 时间从 85.5 分钟降至 52.0 分钟（约 39% 下降）；审查交互占总 wall-clock 的 82.0%（Fold clothes）与 89.7%（Bottle disposal）。
  • 成功率：平均 97.19% vs. 基线 GPT-as-Policy（π_0.5 + GPT-6 Astra）80%，提升 17.19 个百分点；Build tower 60%→93.75%、Classify objects 60%→100%、Bottle disposal 100%→100%、Fold clothes 100%→95%。
  • 审查分配：Build tower 调用次数 40→13.4（约 75% chunk 自动执行）；Classify objects 94→68.2（约 24% 自动执行）；未知上下文触发从 35→16（Fold clothes）、142→64（Bottle disposal）。
  • 自动执行跨度：连续无审查 chunk 的中位跨度由 30 → 60 控制步（约 2 → 4 个 chunk）。
  • 恢复行为：Classify objects 前 8 个 episode 中 16/16 次恢复事件均回到正常调度；但存在未被检测的任务级失败（Fold clothes 第 17 个 episode 审查 20 次仍未触发恢复，原生得分 0.2）。
  • 局限性：仅四个仿真任务、单一策略/审查器组合；记忆表示依赖 RGB + 本体状态，更换传感器接口需适配；绝对时间收益受审查器延迟与硬件影响。
