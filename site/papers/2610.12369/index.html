Card 02 论文概述

论文概述

  • 论文提出将具身世界建模为具身图灵机（Embodied Turing Machine）：纸带是机器人与环境状态，规则是策略；若状态可被准确表示，则决策可完全由代码编写。
  • 据此提出 Code-Only-as-Policy（COAP）：由代码从相机图像与本体感觉中测量并跟踪机器人、环境与任务状态，并完全基于该状态做出决策。
  • 目标是在测试时不使用任何 VLM 或 VLA 的前提下，探索纯代码策略在具身任务上的性能上限，并将其作为支撑递归自我改进（RSI）的媒介。
Card 03 核心贡献

核心贡献

  • 提出 Code-Only-as-Policy 新范式：同一份代码适用于同任务的多个 episode，不同任务共享同一代码库，运行期不含模型。
  • 系统分析代码相对 VLA 与 Agent Harness 的三大优势：显式状态（Explicit State）、可执行性（Execution）、可扩展性（Extensibility）。
  • 提出以代码为媒介的 RSI 闭环：编码智能体在固定规则（禁止单 episode 作弊、测试时禁用 oracle 状态）下自动总结、编写、调试代码，每个改动可控且可回溯。
  • 在 RoboDojo 42 个双臂任务上达到 70.24% 成功率，比此前最优方法高 38.9%，且测试时无模型在环。
  • 指出 COAP 可作为高效数据引擎，稳定生成成功轨迹，用于训练 VLA、Agent-as-Policy 与 Harness VLA。
Card 04 方法描述

方法描述

  • 状态表示：将状态分为三部分——环境状态（物体位姿、尺寸、类别与空间关系）、机器人状态（关节角、末端位姿、夹爪开合与可达位姿）、任务状态（阶段、夹爪分配、重试计数与需记忆信息）。
  • 状态转移：形式化为 (x_{t+1}, a_t) = F_θ(x_t, o_t)，代码 θ 在运行期冻结，仅状态 x_t 变化，因此同一程序可跑不同 episode 布局。
  • 感知即代码：基于 NumPy 与 OpenCV 实现，投影机器人网格并掩膜，利用与桌面平面的射线求交 p = c + λd, λ = (z₀ − c_z)/d_z 恢复物体位置，再通过已知 3D 形状搜索位置与偏航角做匹配。
  • 分层共享库：任务程序调用对象代码，对象代码调用抓取/放置/推/倒等操作代码，再调用感知与运动代码；任务代码只指定"做什么"，底层决定"怎么做"，83% 的代码跨任务共享。
  • 扩展方式：新任务可组合（compose）、继承（inherit）并覆盖单个决策，或为共享函数添加默认关闭参数（default-off parameter）；后者提供兼容性保证 B_i(θ+δ, o) = B_i(θ, o)。
  • RSI 改进循环：编码智能体在独立 git worktree 中检查失败运行的记录状态，定位出错变量或规则并提交 diff，形成可运行代码分支集合 C_k = {θ_k + Δ_{k,1}, …, θ_k + Δ_{k,m}}。
  • 接受准则：分支须通过 CPU 数值场景与 IK/碰撞检查，并在验证集上满足 J_q(θ_k+Δ; V_q) ≥ J_q(θ_k; V_q) + ε_q 才被合并，保证性能单调不减。
Card 05 数据集与资源

数据集与资源

  • 评测基准：RoboDojo，共 42 个双臂操作任务，分为 Memory（6）、Precision（8）、Open（8）、Generalization（12）、Long-Horizon（8） 五类。
  • 输入：指令、三路 RGB 图像（头部 + 双腕）、关节角、末端位姿与夹爪指令回显。
  • 智能体模型：Claude Opus 5.5 Max 编码智能体，自主编写库与任务代码、运行测试与评测并自行调试。
  • 训练/推理资源：运行期在 CPU 上执行，无模型推理、无网络调用；开发不使用基准测试集。
Card 06 评估与结果

评估与结果

  • 评估协议：在 RoboDojo 统一协议下与 VLA、世界模型（WAM）、Agent Harness 及代码类方法对比，报告整体成功率（SR）与基准进度分（Score）。
  • 主要指标：SR（整任务成功 episode 占比）与 Score（基准进度分）。
  • 关键结果：COAP 整体 SR 70.24%，高出此前最优方法 38.9 个百分点；对比基线如 PhysicalRSI（31.38）、GPT-6 Astra（22.48）、Awomo-0.5（29.64）、VPP2-Preview（25.62）、Simate-beta（27.96）等。
  • 优势验证：显式状态使决策可检查可回溯；执行层可灵活回退重试、在线运行快且成本低；可扩展性使新任务复用/继承代码库，能力可累积（83% 代码复用）。
  • 局限与上界：COAP 的上界取决于状态表示的精度与代码逻辑的鲁棒性；其弱点主要在泛化性，需要少量任务特定代码逻辑。
