PonderPounce: A Pretrained MLLM as an Episode Context Engine for Robot Control

2026-08-25 · 原文 · 翻译 · 2608.24115

论文提出 PonderPounce 系统，将预训练多模态大语言模型（MLLM）的原生因果上下文重新利用为机器人控制的"情景上下文引擎"（episode context engine），而非构建专门的情景记忆模块。 系统由两个异步组件组成：Ponder（System 2 MLLM）负责累积 episode 观察、演示与内部认知；Pounce（System 1 VLA）接收最新认知 token 及其年龄，快速生成动作。 核心解决的是"长时程记忆依赖"与"测试时演示条件化"两类上下文相关控制问题。在 RoboMME 上，仅看当前观察的基线的成功率仅 17.93%，而人类达到 90.50%，凸显了使可操作上下文可用于控制器的重要性。

Card 02 论文概述

论文概述

  • 论文提出 PonderPounce 系统，将预训练多模态大语言模型（MLLM）的原生因果上下文重新利用为机器人控制的"情景上下文引擎"（episode context engine），而非构建专门的情景记忆模块。

  • 核心解决的是"长时程记忆依赖"与"测试时演示条件化"两类上下文相关控制问题。在 RoboMME 上，仅看当前观察的基线的成功率仅 17.93%，而人类达到 90.50%，凸显了使可操作上下文可用于控制器的重要性。
Card 03 核心贡献

核心贡献

  • 独立可扩展的预训练 MLLM 情景引擎：复用 MLLM 原生因果上下文保留 episode 观察与演示，无需专门记忆库、检索策略或历史压缩器；System 2 容量可变而不改变快速控制器架构。
  • 异步连续上下文到控制接口：通过一个连续认知 token 及其年龄连接两个预训练模型，二者在解耦时钟上运行并端到端联合训练；过渡触发的子目标生成和演示推理监督通过 LM 头接地，文本保留在 System 2 内部。
  • 跨记忆类型与跨具身演示条件化的实证验证：在 RoboMME 上两个数据规模均超越最强非 oracle 基线；9B 情景引擎相比 0.8B 在相同接口下提升 10.79 个百分点；推理期干预证明控制依赖于传输的认知；接口可迁移至 RoboCasa-DC 的跨具身演示条件化任务。
Card 04 方法描述

方法描述

  • Ponder 架构：在查询时将当前观察追加到只增（append-only）的因果上下文，上下文包含指令、可选演示、内部生成的子目标文本和演示推理以及早期认知载体；预测过渡 token，若为"是"则先生成子目标文本，再插入载体位置；载体最终隐藏状态形成认知向量 C_t，无需解码或池化。
  • Pounce 架构：接收指令、当前观察、本体感受，以及由最新认知 token 经投影和其正弦编码年龄组成的前缀；动作头预测动作块并以 20 Hz 播放。
  • 训练与接地：从预训练检查点初始化并端到端联合训练，无需子系统预训练或桥梁预训练；损失为动作流匹配 MSE 与 LM 头 token 交叉熵的加权和；流匹配梯度仅通过认知 token 传递至 Ponder。
  • 异步调度：训练时对 Pounce 采样对数正态间隔约 100 ms，Ponder 约 1 s，计算延迟 300 ms；评估时两者均 1 Hz 运行，动作 20 Hz 播放。
  • 推理优化：使用 StaticCache 仅编码新 token，避免重编码历史；融合 Triton 内核将 Pounce 延迟从 142 ms 降至 25 ms（5.7×），支撑 1 Hz 模型时钟和 20 Hz 播放。
Card 05 数据集与资源

数据集与资源

  • RoboMME：完整 16 任务套件，按 Counting、Permanence、Reference、Imitation 四个任务族组织；评估使用 1× 基础数据和 9× 扩展数据两个规模。
  • RoboCasa-DC：Category-Balanced / Cross-Embodiment Demonstration 设置，覆盖五个留出任务。
  • Ponder 初始化自 Qwen3.5-9B（亦测试 0.8B 变体），使用一个认知载体（K=1）；Pounce 在 RoboMME 上初始化自 π₀.₅ 3.6B 动作模型，在 RoboCasa-DC 上初始化自 GR00T N1.5 3B 模型。
  • 评价各任务 50 个 episode（RoboMME 共 800 个/run，三 run 取均值；RoboCasa-DC 每任务 50 个，五 run 取均值）。
Card 06 评估与结果

评估与结果

  • RoboMME 主结果：PonderPounce 在 1× 数据下平均成功率 60.83%（Counting 74.67 / Permanence 62.83 / Reference 72.17 / Imitation 33.67），显著优于 FrameSamp+Modul 的 44.51%；9× 数据下 75.54%，优于其 57.88%；而当前观察 π₀.₅ 仅 17.93%，加入过去动作仅 19.73%。
  • RoboCasa-DC 结果：PonderPounce 平均成功率 12.5% ± 0.9，优于最强已发表基线 SeeTraceAct 的 11.6%；将认知替换为学习空状态时降至 8.6%，证明控制依赖认知传输。
  • 监督消融：去掉演示推理目标后平均成功率从 60.83% 降至 48.21%；去掉全部 LM 头接地降至 27.96%；子目标文本参考接口达到 59.96%，连续认知精度上与其竞争而非绝对优越。
  • 认知刷新分析：若只传送过渡时刻的认知并将中间状态保持固定，平均成功率骤降至 1.83%，说明报告检查点依赖子目标内部的及时刷新；离线 staleness 诊断中，1 s 刷新训练检查点在 4.3 s 时归一化损失从 1.00× 升至 9.22×，而 4 s 训练可在推迟下缓解至 1.14×。
  • 容量迁移：预训练 9B Ponder 达到 60.83%，比预训练 0.8B 的 50.04% 高 10.79 个百分点；随机初始化的 9B 训练不稳定且成功率为 0%，表明当前端到端流程依赖预训练上下文模型。
  • 服务延迟：认知刷新 p50 为 78 ms，动作模型调用 p50 为 25 ms，支持 20 Hz 动作播放。
