Card 02 论文概述

论文概述

  • 论文研究 World Action Models（WAMs） 的推理加速问题：WAM 结合视觉动态建模与动作生成，但推理延迟高，限制了机器人的实时响应能力。
  • 现有方案存在两条局限路径：FastWAM 类方法需专门定制架构；通用缓存方法（如 TeaCache）只利用特征冗余，无法刻画闭环控制中不断变化的计算需求。
  • 目标是提出 RealtimeWAM——一个通用、免训练（training-free） 的框架，通过协调并行执行与自适应计算，在多种 WAM 架构上实现低延迟推理。
Card 03 核心贡献

核心贡献

  • 设计依赖感知的并行调度：利用逐层依赖关系，让观测处理（Prefill）与动作预测（以及存在时的未来视频生成）重叠执行。
  • 提出硬件感知的 Token 复用策略：减少 Prefill 负载，并利用 GPU 延迟平台期（latency plateau）刷新更多信息量大的 token。
  • 提出运动自适应精化（motion-adaptive refinement）：根据粗动作预测的位移幅度自适应调整 Transformer 残差缓存的刷新次数。
  • 在 2 种 WAM 架构、3 个仿真基准、5 个真实世界任务上进行系统评估，并通过受控实验拆分执行调度、token 分配与预测精化的贡献。
Card 04 方法描述

方法描述

  • WAM 推理剖析：请求延迟可分解为 T_t ≈ T_first(R_t) + Σ T_full,j + T_light + T_finish，其中 R_t 控制第一阶段（Prefill + 首次预测）工作量，N_t 控制后续精化次数。
  • 依赖感知并行执行：VAE 编码与指令/条件 K/V 预准备并行；观测 K/V 在投影后立即释放，使预测可与剩余 Prefill 的注意力与 FFN 重叠；配合融合算子、预分配缓冲与 CUDA Graph 重放降低开销。
  • 硬件感知 Token 复用：离线剖析得到执行容量集合 B，用 RGB 变化确定必需刷新集合 D_t，按 r_t = \|D_t\|+ ⌈α(M-\|D_t\|)⌉ 选取最小容量 b_t；再用归一化首层特征变化 s_{t,i} 排序剩余位置填满容量，形成刷新集 R_t；选中位置更新 FFN 缓存，其余复用上一时刻缓存。
  • 运动自适应精化：缓存 Transformer 输入到输出的残差；在两次共享的前缀刷新后解码粗动作，用最大位移 m_t 与阈值 τ 决定 N_t = 2 + 2·1[m_t ≤ τ]（2F / 4F 调度），大运动偏向快速重规划，小调整保留更多精化；精化从同一初始去噪轨迹（相同噪声与条件）续接。
  • 关键创新：不改架构、不训练选择器，将“何时并行”与“算多少”统一在单次请求内自适应分配。

数据集与资源

  • 真实世界任务：5 个真实操作任务（如传送带堆叠羽毛球等动态操作场景）。

Card 06 评估与结果

评估与结果

  • 评估设置：成功率（SR）+ 完整请求延迟（ms），并计算相对 Native 的加速比；2F/4F 表示 10 次 Euler 更新中执行 2/4 次完整 Transformer 评估。
  • 整体加速（Table 1，RTX 4090）：

- FastWAM：平均延迟 214.33 ms → 24.09 ms，加速 8.90×；平均成功率 82.77% → 82.75%（仅降 0.02 个百分点）。

- OpenWAM：平均延迟 672.83 ms → 63.09 ms，加速 10.67×；平均成功率 87.94% → 87.41%（降 0.53 个百分点）。

- 相对同样启用编译与 CUDA Graph 的 Native，加速为 4.14×（FastWAM） 与 7.15×（OpenWAM）。

  • 与缓存基线对比：TeaCache 为最快竞争基线（49.28 / 245.99 ms），但平均成功率低于本方法；BAC 在 OpenWAM 上成功率为 87.77%（略高于 87.41%），但延迟高达 305.08 ms。
  • 延迟来源拆解（Table 2，累积优化）：CUDA Graph + 编译后，并行执行把首帧延迟从 36.21 → 17.77 ms（FastWAM）、60.62 → 37.12 ms（OpenWAM）；Token 复用进一步降至 17.69 / 31.62 ms；固定 10F 下请求延迟从 214.33 → 29.47 ms（FastWAM）、672.83 → 217.24 ms（OpenWAM）。
  • 消融实验（OpenWAM / RoboTwin）：

- 关闭 token 复用：93.8% @ 72.10 ms（全方法 93.4% @ 63.76 ms）。

- 随机选 token：成功率降至 91.3%（同等刷新数量），说明 RGB/特征引导选择更有效。

- 容量填充：从 92.1% @ 61.78 ms 提升到 93.4% @ 63.76 ms（首帧 30.76 → 30.96 ms）。

- 运动门控：93.4% @ 63.76 ms，优于随机 2F/4F 的 91.1% @ 64.77 ms；固定 2F 为 89.6% @ 54.70 ms，固定 4F 为 93.7% @ 95.26 ms——自适应策略在接近 4F 成功率的同时显著更低延迟。

  • 真实世界结果：在 5 个真实任务上，RealtimeWAM 相比 Native 推理平均成功率分别提升 17.2 个百分点（FastWAM） 与 37.2 个百分点（OpenWAM）；论文指出传送带任务存在约 90 ms 的经验延迟阈值，超过后成功率明显下降（Figure 1）。
