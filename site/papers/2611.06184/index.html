Can Astra Solve RoboMME without Breaking the Bank?

2026-11-04 · 原文 · 翻译 · 2611.06184

Card 02 论文概述

论文概述

  • 论文面向 RoboMME 机器人记忆基准，研究如何用「高层规划器 + 低层 VLA」的分层系统完成需要记忆（遮挡前物体位置、演示动作顺序、重复次数）的操作任务。
  • 核心问题是：大型视觉语言规划器（如 GPT-6 Astra）虽然能读懂历史信息，但在每个动作块之前都调用它既慢又贵，而且大多数调用是冗余的。
  • 目标是既要保持高成功率，又要把昂贵规划器的调用次数压到最低，从而低成本地解决 RoboMME。
Card 03 核心贡献

核心贡献

  • 提出三层系统：System 2（GPT-6 Astra 规划器）负责生成接地子任务，System 1（π0.5 VLA 策略）负责执行动作块，System 1.5（微调 Qwen3-VL-4B 监视器）负责判断子任务是否完成。
  • 设计事件触发协调机制：只有在监视器报告完成或触发特定任务事件时才再次调用 Astra，其间 VLA 持续用新观测执行同一指令，保持闭环控制。
  • 显式管理任务相关历史：在每次请求中向无状态规划器发送任务所需的演示视频、执行记忆帧和文本进度记录，并按任务配置输出模板。
  • 在 RoboMME 上以平均 3.63 次 Astra 调用、80.84 秒/回合 取得 79.13% 成功率，比最好的非 oracle 基线高 34.62 分，仅比 oracle 低 4.95 分。
  • 将规划器调用从「每动作块一次」（约 24.62 次）降至 3.63 次，等价减少约 85.3% 的规划器调用。
Card 04 方法描述

方法描述

  • System 2（高层规划器）：在每次规划事件中，GPT-6 Astra 依据当前图像、执行起始图像、演示视频/执行记忆和历史记录生成一条带像素坐标的接地子任务指令；它不保留任何状态，所有历史随请求发送。
  • System 1（低层执行）：使用 RoboMME 发布的接地子目标 π0.5 策略，每个动作块 H = 16 步，同一指令可跨多个动作块复用，每块都用最新观测重新预测。
  • System 1.5（视觉进度监视器）：以 Qwen3-VL-4B-Instruct 为基础，用 LoRA（rank 16，冻结视觉编码器，训练 2 个 epoch） 微调为二分类完成判断；输入 10 张图像（8 张相隔 3 步的最近前视帧、指令发起时的参考帧、当前腕部图像）。
  • 任务特定事件：StopCube 中监视器在方块到达目标前约 16–32 步触发重新规划；ButtonUnmaskSwap 中 Astra 需核验第二次按键是否真的完成。
  • 推理调度：沿用官方两系统评测，Astra 推理时模拟器暂停，因此规划耗时计入实际耗时，但不消耗步数预算（否则 VLA 会在 Astra 返回前耗尽 1300 步预算）。
  • 部署细节：Astra 以 medium 推理强度通过 Codex CLI 调用，调用间隔至少 20 秒；规划输出需通过模板校验后才下发给 VLA。
Card 05 数据集与资源

数据集与资源

  • 数据集：RoboMME 官方测试集，16 个任务、4 个套件（Counting / Permanence / Reference / Imitation），每任务 50 回合，共 800 回合，每回合 1300 步预算。
  • 监视器训练数据：由 RoboMME 演示构建的 71,835 个样本，使用录制的子任务边界作为标签。
  • 模型：GPT-6 Astra（规划器）、π0.5 接地子目标检查点（VLA）、Qwen3-VL-4B-Instruct + LoRA（监视器）。
  • 计算资源：VLA、监视器与模拟器共享单张 NVIDIA L40S GPU。
Card 06 评估与结果

评估与结果

  • 评估环境：RoboMME 官方测试集，指标为模拟器任务成功率，并统计规划器调用次数与失败/超时案例。
  • 总体结果：79.13% 成功率，套件层面 Permanence 94.00、Reference 92.00、Counting 69.50、Imitation 61.00。
  • 对比基线：π0.5 17.93、SAM2Act+ 21.37、GroundSG+QwenVL 32.70、GroundSG+Gemini 11.56、MemER 42.38、FrameSamp+Modul 44.51、GroundSG+Oracle 84.08；本系统比最强非 oracle 基线高 34.62 分。
  • 效率：平均 3.63 次 Astra 调用、24.62 个动作块、80.84 秒每回合，规划调用减少约 85.3%。
  • 失败分析：167 个失败回合中 103 次失败、64 次超时；StopCube 与 InsertPeg 各仅 9/50 成功，合计占 82 个失败回合（StopCube 全为失败，InsertPeg 多为超时）。
  • 亮点任务：ButtonUnmask、VideoUnmaskSwap、VideoPlaceButton 均达 100%。
  • 局限：未做事后消融、未测 token/金额成本、未测监视器闭环错误率，且历史选择与事件规则按任务手工配置，迁移性受限。
