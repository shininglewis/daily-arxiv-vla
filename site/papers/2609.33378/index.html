Card 02 论文概述

论文概述

  • 论文提出 Recursive Harness Distillation (RHD)，将强智能体（Astra）与 VLA 交互的经验蒸馏为可复用的 playbook，供轻量智能体（Luna）使用，并在执行反馈中递归改进，无需更新模型参数。
  • 目标：解决 VLA 在任务和环境变化时难以诊断失败、自适应执行的问题，以及强模型部署成本高、经验难以迁移到轻量模型的问题。
  • 核心思想：通过强智能体积累干预经验并蒸馏为外部指导（harness），让轻量智能体在有限 token 预算下有效操控冻结的 VLA，并可跨智能体复用。
Card 03 核心贡献

核心贡献

  • 提出 RHD 框架：强智能体将 VLA 交互经验蒸馏为 playbook，并通过轻量智能体的执行反馈递归精炼，实现干预经验的积累、改进与跨智能体复用。
  • 设计三类 VLA 干预接口：instruction（指令编辑）、attention（注意力引导）、action（动作修正），并将 playbook 优化形式化为对接收智能体诱导策略的策略优化问题。
  • 在 SimplerEnv Bridge 和三个真实机器人任务上验证：真实场景成功率从 37.3% 提升到 64.0%；Bridge 上轻量智能体配合 playbook 达 66.7%，超过无 playbook 的强智能体基线。
  • 同一 playbook 也能提升强智能体（达 79.2%），且递归精炼在提升成功率的同时降低或维持平均 token 使用量。
  • 分析表明 playbook 可捕获操作洞察（观察解读、干预选择、物理结果验证），且轻量智能体部署成本显著低于强智能体（约 5.5 倍 成本差距）。
Card 04 方法描述

方法描述

  • RHD 循环：强智能体（Astra）先与冻结 VLA 交互，将经验蒸馏为初始 playbook；轻智能体（Luna）用 playbook 指导执行；强智能体审查执行反馈并修订 playbook，形成递归闭环。
  • 三类干预：指令干预 \(u_t^I\) 修改语言输入，注意力干预 \(u_t^F\) 修改内部特征注意力，输出干预 \(u_t^A\) 修改生成动作；每种干预含 identity 选项以保持 VLA 不变。
  • 策略优化视角：定义目标 \(J_S(P)=\mathbb{E}_{\tau\sim p_\mathcal{D}}[Y(\tau)]\)，收益为任务成功概率；用有限时域性能差恒等式识别改进目标，强调在接收智能体实际遇到的历史上诱导更好决策。
  • 递归更新：教师基于自身经验 \(\mathcal{E}_T\) 和接收智能体经验 \(\mathcal{E}_{S,0:k}\) 提出修订集合，在 \(n\) 个开发实例上评估，接受满足教师成功率阈值 \(\eta\) 的首个候选 playbook。
  • 关键创新：不更新任何模型参数，仅通过外部文本指导（playbook）积累知识；playbook 指定干预条件、操作方式及后续验证检查。
Card 05 数据集与资源

数据集与资源

  • 仿真数据集：SimplerEnv Bridge（WidowX 操作任务），包含 spoon-on-towel、carrot-on-plate、cube stacking、eggplant-in-basket 四类任务；使用 GR00T-N1.7-SimplerEnv-Bridge 检查点并冻结，输入 256×256 RGB、机器人本体感知与语言指令。
  • 仿真数据划分：每任务预留 12 个初始配置用于开发、12 个用于评估，每个划分共 48 个实例；最大 episode 长度 120 步（eggplant-in-basket 为 240 步）。
  • 真实世界平台：7-DoF Franka Panda 机械臂，配备腕部、前方和右侧 RGB 相机；任务为 Cube-to-Tray、Cube Stacking、Button Pressing。
  • 真实数据：每个任务采集 50 条人类遥操作演示，微调 π0.5 策略；评估时每个任务 25 次试验，共 75 次，物体位置在 50cm×50cm 工作空间内随机化。
  • 智能体模型：强智能体 GPT-6 Astra，轻量智能体 GPT-5.6 Luna；干预能力包括最多 512 字符指令替换、0–4 强度注意力 logit 偏置、最多 5 个控制步的末端执行器与夹爪修改。
  • 成本参数：Luna 每百万 token：标准输入 $0.20、缓存写入 $0.25、缓存读取 $0.02、输出 $1.20；Astra：未缓存输入 $10、缓存输入 $1、输出 $50；未提及 GPU/TPU 训练资源。
Card 06 评估与结果

评估与结果

  • 仿真基准：在 SimplerEnv Bridge 上对比 GR00T 单独、Luna 无 playbook、初始 playbook、精炼 playbook 及 Astra 使用同一 playbook。
  • 仿真结果：GR00T 单独 41.7%，Luna 无 playbook 43.8%，Luna + 精炼 playbook 66.7%（提升 22.9 个百分点），Astra + 同一 playbook 79.2%；初始 playbook 反而使 Luna 降至 31.3%。
  • 真实世界结果：π0.5 单独 37.3%，Luna + π0.5 无 playbook 0%，Luna + π0.5 + 精炼 playbook 64.0%（75 次试验总体成功率）。
  • 教师模型消融：Luna 自蒸馏（Luna-to-Luna）精炼 playbook 仅 22.9%，显著低于 Astra 作为教师的 66.7%，说明强教师对 RHD 至关重要。
  • 干预站点消融：移除 instruction 编辑造成最大性能下降，表明 playbook 引导的指令编辑与直接动作修正共同贡献增益。
  • 成本分析：在相同测试集上，Luna 总推理成本约 $30.03，Astra 约 $164.61；每 episode 平均成本分别为 $0.63 和 $3.43，Astra 约贵 5.5 倍。
  • 分析发现：playbook 包含六类操作洞察（遮挡后物体重识别、弱提升与空提升区分、指令-动作不匹配处理、注意力恢复、修正保留、放置支撑验证），递归精炼在多数任务中降低每 episode 平均 token 使用。
