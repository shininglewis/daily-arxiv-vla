论文概述

  • 论文提出 AW-0，一个“智能体世界动作模型”（Agentic World Action Model）框架，把代码规划与视频+动作联合预测统一到同一个生成模型中。
  • 要解决的问题：现有世界动作模型（WAM）具备视觉预见与未来预测能力，但缺乏显式的组合式技能复用机制；而智能体机器人（agentic robotics）虽能通过代码规划复用技能，却缺乏对物理动力学的预测性基础。

Card 03 核心贡献

核心贡献

  • 提出 AW-0：基于 Mixture-of-Transformers (MoT) 的框架，将代码专家（code expert）引入世界动作模型，同时对代码、视频、动作三路生成流进行联合去噪（joint denoising）。
  • 提出自动化数据标注与技能发现流水线：使用代码智能体为机器人轨迹与人类视频轨迹标注时间对齐的技能程序，并将重复出现的例程固化为可复用技能库。
  • 构建并发布结构化技能程序数据集：包含两个具身专属技能库，共 50 个技能条目（YAM 机器人 23 个、自我中心人类演示 27 个）。
  • 提出混合执行策略（Hybrid Actions）：在推理时动态在“程序化技能调用（CaP 式执行）”与“WAM 动作专家直接输出动作块”之间仲裁切换。
  • 实验证明该设计在语言跟随、语义推理与鲁棒性上均优于 VLA 与 WAM 基线，并说明代码在规划、预测、执行之间起到连接作用。
Card 04 方法描述

方法描述

  • 统一条件生成建模：以多视角观测、语言指令、机器人状态和历史程序记忆为条件，联合建模程序 token 序列、VAE 编码的未来视频潜变量与动作块。
  • MoT 三专家架构：代码专家（冻结 Qwen3-VL ViT + LLaDA 式掩码 token 扩散）、视频专家（由 Cosmos-Predict2.5 初始化的视频 DiT）、动作专家（独立动作 DiT，额外接收机器人状态）。
  • 掩码联合注意力：专家内部双向注意力，专家之间按 代码 → 视频 → 动作 的顺序做块状因果注意力，使语义计划能在整个去噪过程中引导视频与动作生成。
  • 模态特定加噪：视频与动作使用连续流匹配（flow matching），含分布偏移与噪声重采样以提供更具信息量的预测引导；代码使用离散吸收式掩码与交叉熵损失。
  • 训练目标：带重要性权重的复合损失（视频流匹配损失、动作流匹配损失、代码掩码重建交叉熵），按批归一化后加权求和。
  • 自动标注流水线：Gemini 3.1 Pro 依据预定义的声明式 API 编写子任务级程序，Claude Code + Claude Opus 4.8 作为协调者提炼任务通用技能；冻结技能库后，通过接触与运动模式匹配复用缓存程序，否则新生成并入库。
  • 混合动作推理：解码出的代码片段仅在通过有效性与进度检查时才接管当前阶段，否则回退到同一前向传播的动作块。

Card 06 评估与结果

评估与结果

  • 仿真基准 RoboTwin 2.0（50 任务 × 50 次 rollout），两种设置：*clean* 与 *random*（背景、纹理、光照、桌面高度、干扰物域随机化）。

- AW-0 平均成功率 50.7%，优于所有基线（π0.5 41.3%、WLA 34.2%、DreamZero 25.6%、EgoScale 14.5%）。

- clean 设置 80.8%，比最强基线 WLA（64.8%）高 16.0 个百分点。

- random 设置 20.6%，低于 π0.5（27.7%），但高于 DreamZero（17.6%）、WLA（3.6%）、EgoScale（2.9%）。

- 混合执行在 random 设置提升至 29.2%（超过 π0.5），但 clean 降至 63.1%，平均 46.2%，体现出鲁棒性与干净性能之间的权衡。

  • 真实世界 8 任务（3 训练种子 × 16 次 rollout，评分标准打分）：AW-0 平均 71.1%，比最强基线 DreamZero（46.0%）高 25.1 个百分点；在语言跟随类任务（*Arrange Fruits* 91.7%、*Flip Scoreboard* 68.8%）与接触丰富/灵巧任务（*Replace Lightbulb* 75.0%、*Solve Cube* 72.1%）均领先。
  • 混合执行真实实验：*Fold and Stack Towels* 上 90.6% vs 动作块直接执行 84.4%。
  • 消融结论：

- 注意力顺序 C→V→A 最优，代码应直接引导视频生成而非仅参与后期推理。

- 代码专家使用专用 ViT 视觉条件（71.1%）显著优于复用 Wan2.2 VAE 特征（55.6%），在 *Pack Backpack*（64.6% vs 39.6%）与 *Solve Cube*（72.1% vs 53.9%）提升明显。

- 完整程序 > 无注释代码；去掉技能调用明显下降（*Deal Poker* 58.3% vs 42.0%）；完整程序在 8 个任务中 7 个优于纯自然语言子目标。

- 联合去噪优于自回归（AR）：7/8 任务更好，平均 71.1% vs 54.5%，且推理延迟 0.23 s vs 0.55 s（2.39× 加速）；相较多无代码版本（0.19 s）仅增加 0.04 s。
