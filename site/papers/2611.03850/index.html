Card 03 核心贡献

核心贡献

  • 评估时间去向的量化剖析：在单张 RTX 4090 上，官方 StarVLA LIBERO-Long 评估器 55% 时间花在 CPU 上的仿真与逐步处理、GPU 平均利用率 14.3%；增加仿真器可升至 45.7%，再加一个 Policy 副本升至 87.7%；RoboTwin 每步渲染三路相机，而策略每 16 步才读一次观测。
  • 统一的评估接口：模型只需包成一个 Policy 类、基准只需包成一个 adapter（包裹基准自有评估器），适配器覆盖六个基准族；固定配置可复现官方 StarVLA 在 LIBERO-Long 上全部 500 个 episode 的成功结果。
  • 调度加速：把仿真器 worker 与 Policy 副本作为两个独立进程池（规模分别为 *K* 与 *g*），用时间受限的并发搜索（diagonal search）自动定容，并按 j mod N 做确定性分片跨 GPU 实例扩展。
  • 运行时优化：支持 chunk-boundary observation（按 Policy 声明 stride 渲染，stride=1 即官方节奏）、复用 SAPIEN Engine/Renderer、消除控制循环重复计算、种子缓存与场景初始化缓存，且只删除既不影响策略输入也不影响得分的仿真工作。
  • 实测大幅提速且结果一致：LIBERO-Long 单卡 500 episode 由 2990 s 降至 485 s（6.16×）；RoboTwin Easy 四卡 500 episode 由 359.7 分钟降至 14.4 分钟（25.04×），成功结果与终止步完全一致。
Card 04 方法描述

方法描述

  • Policy 抽象：一个类封装 load / reset / act / act_batch / end_episode / unload 生命周期；声明所需观测特征（如 images.head、state.joints、language.instruction）、支持的基准与套件、动作 chunk 长度、动作表示与观测 stride；模型侧预处理（裁剪、归一化、tokenize、动作反变换）全部留在 Policy 内。
  • 基准适配器：包住基准的原生评估器，保留任务定义、初始状态、终止条件与打分；只负责构造 work item、启动原生 rollout、观测/动作翻译与解析 episode 记录。
  • 双运行时架构：Control Runtime 负责展开 manifest（episode key = 任务/回合/种子）、切分 work item、启动 *K* 个仿真 worker 与 *g* 个 Policy 副本、聚合并校验结果；Simulation Runtime 在每个 worker 内运行插桩后的原生评估器。
  • 并发搜索（Algorithm 1）：先用真实负载做短探针（每 worker 3 个 work item，丢弃首项暖机、测稳态吞吐 *q*、占用核数 *c*、GPU 利用率 *u*、限流 *t*、每副本显存 *v*）；worker 阶段按 1 副本/GPU 倍增 *K*，直到增益低于 25%（κ=0.25） 的拐点；replica 阶段按 K = r·g 同步扩副本，直到增益低于 3%（ε=0.03）；受 WorkerCap、ReplicaCap、FitsMemory、WithinLimits（u≤0.95、t≤0.40）约束，探针上限 τ_c=15 min、整体预算 τ=30 min。
  • 解耦与隔离：worker 与副本不共享解释器，可绑定互相冲突的依赖库；副本可在实例内跨多张 GPU 分布，消息为本地 request–response 并携带 episode id 以复用同一加载模型。
  • 容错与一致性：work item 原子认领、幂等发布；worker 崩溃/显存 OOM 时回收该项、丢弃部分记录并重启替换 worker 重放（OOM 时降低该 GPU 并发），Policy 副本退出则整体中止；聚合前校验覆盖性与 episode key 唯一性。
  • 跨实例分片合并：支持 record-tree merging 与 result-only reduction 两条合并路径，非可加指标由计数重算。

  • 软件与工程：Python 包形式分发，Control Runtime、仿真 worker、Policy 副本以独立进程经 Unix domain socket 通信；支持 CUDA MPS 与本地/共享存储加载仿真器与数据集。
Card 06 评估与结果

评估与结果

  • 基线：官方 StarVLA 评估器、RLinf、vla-eval（调至其最优配置）；RoboTwin 单卡单仿真器单模型为对照基线。
  • 指标：任务成功率与逐 episode 结果一致性（成功率、终止步完全相同）、评估墙钟时间与加速比、稳态吞吐 q（控制步/秒）、CPU 占用核数、GPU 利用率、限流、每副本显存、以及 worker/副本/GPU 数量下的可扩展性。
  • 保真性：固定 RoboScope Kit 配置复现官方 StarVLA 在 LIBERO-Long 上全部 500 个成功结果；四卡 stride-16 的 RoboTwin 运行与单卡 stride-1 运行在全部 500 个 episode 的成功结果与终止步上完全一致。
  • LIBERO-Long（单张 RTX 4090，500 episode）：并发搜索选出 12 workers / 3 replicas，较官方 StarVLA 快 4.45×、较 RLinf 快 2.78×、较 vla-eval 快 1.52×；启用 CUDA MPS 后选出 16 workers / 4 replicas，分别快 6.16× / 3.85× / 2.10×（485 s vs 2990 s）。
  • RoboTwin Easy（四卡，500 episode）：结合调度与 chunk-boundary observation，由 359.7 分钟降至 14.4 分钟，较单卡基线快 25.04×，结果与终止步完全一致。
  • 消融：分别验证「仿真/推理分离」「并发搜索及其代价」「CUDA MPS 下的搜索」「运行时优化（Engine 复用、控制循环去冗余、stride 渲染）」以及「优化后的四卡 RoboTwin 运行」，并给出 worker 数、副本数与 GPU 数的扩展曲线及瓶颈迁移分析。
