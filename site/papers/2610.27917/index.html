Card 02 论文概述

论文概述

  • 论文聚焦历史依赖型机器人操作（history-dependent manipulation）任务，这类任务中仅凭当前观测无法决定下一步动作，必须依赖任务上下文与交互历史。
  • 采用分层框架：高层用视觉语言模型做子目标推理，低层用视觉-语言-动作（VLA）模型执行动作；核心难点在于如何准确、及时地判断子目标是否完成并更新任务记忆。
  • 论文指出相似观测可能对应不同执行阶段（如按压与抬起的同一位置），过早记录“完成”会误导后续子目标推理，因此提出以事件驱动的记忆更新机制替代固定频率或异步更新。
Card 03 核心贡献

核心贡献

  • 提出 EventSync 分层记忆框架：高层 Memory Reasoner 管理任务记忆并生成子目标，低层 Action Executor 执行动作，独立的轻量级 Event Monitor 提供完成反馈。
  • 设计事件驱动的任务记忆更新机制：Event Monitor 融合视觉观测与末端执行器轨迹判断操作是否完成，仅在获得完成证据后才将当前子目标写入已完成历史并触发下一次高层推理。
  • 构建统一的监控预测接口，同时支持机器人自身操作完成判定与环境事件增量预测（如传送带物体通过计数），并保留跨查询的时序状态。
  • 在 RoboMME 仿真基准与四类真实机器人任务上进行了系统评估与消融，验证了事件驱动更新对减少“提前推进”的作用。
  • 实验表明轻量专用监控器优于同等条件下的 4B VLM 监控器，且参数量仅为其约 2.2%、延迟显著更低。
Card 04 方法描述

方法描述

  • Memory Reasoner（R_θ）：基于 Qwen3-VL-4B-Instruct，用 LoRA 微调；负责初始规划（含演示视频的结构化事件序列 + 任务计划）与在线子目标推理，输出含动作指令与图像空间坐标的子目标。
  • Action Executor（π_φ）：基于 π0.5 微调的 VLA 策略，以当前观测、当前子目标、可选视觉历史特征为条件生成动作块；训练动作块长度 20，推理 16。
  • Event Monitor（F_ψ）：轻量模块，用冻结的 DINOv2-Base 提取图像 token，结合末端执行器轨迹 token、事件条件 token 与上一时刻时序状态，经共享的两层 Transformer 融合，同时输出完成概率与事件增量分布（后者额外用 GRU 保留跨查询信息）。
  • 关键机制：每个新子目标创建独立事件实例并重置起始时间与监控状态（即使动作描述与之前相同）；基于事件增量的累积判断何时触发下一操作；在动作块更新时检查机器人操作、每 4 个仿真步检查环境事件，真机监控独立运行、查询间隔 0.5 s。
Card 05 数据集与资源

数据集与资源

  • RoboMME 仿真基准：16 个历史依赖任务，覆盖 Counting、Permanence、Reference、Imitation 四类，每任务评估 50 个 episode。
  • 真实机器人平台：Franka Panda 机械臂 + Robotiq 夹爪，7-DoF 关节空间控制；右外置相机 + 腕部相机供执行器使用，右外置相机供推理器与监控器使用，左相机仅用于记录。
  • 四个真实任务：SwingXTimes、UnmaskCube、ImagePickPlace、SequencePickPlace，分别采集 90 / 90 / 150 / 150 条轨迹，混合训练。
  • 模型规模：Memory Reasoner 为 Qwen3-VL-4B；Event Monitor 总计 87.39M 参数（含视觉编码器）。
  • 训练资源：NVIDIA H100 GPU；执行器在仿真数据上训练 80,000 步、真机数据 20,000 步；LoRA rank 16、scaling 32、学习率 1e-4、2 个 epoch；Event Monitor 用 AdamW 训练 30 epoch、学习率 3e-4。
  • 标注：演示数据用 GPT-5.4 生成结构化事件序列与初始任务计划；Event Monitor 用执行事件标签监督，并在事件边界附近重采样训练样本。
Card 06 评估与结果

评估与结果

  • 评估环境：RoboMME 仿真（16 任务 × 50 episode）与四类真机任务（每方法每任务 10 次试验），主指标为任务成功率，辅以在线高层调用次数、平均 episode 墙钟时间、提前完成记录比例等。
  • 整体性能：EventSync 在 RoboMME 上取得 64.5% 总体成功率，超过基准中最佳基线 FrameSamp+Modul（44.5%）20.0 个百分点；不使用执行器视觉历史的变体仍达 62.0%，比同为分层架构的 GroundSG + QwenVL 高 29.3 个百分点。
  • SwingXtimes：无视觉历史变体达 94.0%，相比 GroundSG + QwenVL 的 7.3% 提升 86.7 个百分点。
  • 更新机制对比：相比 Fixed 1:1，成功率提升 6.5 个百分点，高层调用减少 70.8%，平均 episode 时间从 78.09 s 降至 46.74 s（降 40.1%）；与调用量相近的 Fixed 4:1（52.1%）相比高 9.9 个百分点；优化后的异步执行（53.0%）成功率更低。
  • 提前推进分析：SwingXtimes 上含提前完成记录的 episode 从 64.0%（32/50）降至 10.0%（5/50），提前记录占比从 42.5%（134/315）降至 5.7%（18/314），“记忆超前”的步数占比从 27.7% 降至 3.5%。
  • 监控器对比：Event Monitor 在两种执行器下均优于微调 Qwen3-VL-4B 监控器（62.0/64.5 vs 59.8/61.4），单次查询延迟 19.52 ms vs 215.84 ms；去掉轨迹输入使成功率下降 3.0 / 2.0 个百分点。
  • 记忆组件消融：去掉高层在线视觉历史使成功率从 62.0%/64.5% 降至 49.9%/54.5%（降 12.1/10.0 个百分点）；去掉结构化事件预测分别降至 57.1%/61.5%；加入执行器视觉历史（FrameSamp+Modul）使 62.0% 提升至 64.5%。
  • 真机结果：EventSync 在四任务上均最优，SwingXTimes 9/10、UnmaskCube 7/10、ImagePickPlace 9/10、SequencePickPlace 7/10；去掉 Event Monitor 时 SwingXTimes 为 0/10，显示事件监控对重复操作类任务的关键作用。
