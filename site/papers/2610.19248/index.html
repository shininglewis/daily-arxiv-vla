Card 02 论文概述

论文概述

  • 论文提出 PACER（Process-Aware Correction and Evidence Reweighting），一个面向机器人拆解任务的 VLA 策略后训练框架，核心是从自主 rollout、人工纠正和补充干净演示中学习。

Card 03 核心贡献

核心贡献

  • 提出 PACER 框架，将自主 rollout、操作员纠正与补充干净演示统一编译为带类型（typed）的动作 chunk 行，并赋予过程角色（clean/correction/auto_success/partial/failure/excluded）。
  • 设计基于过程证据（progress、proximity、terminal entry、direction、stop、outcome、provenance）与角色乘子的有界行权重，在原生监督动作损失上按样本加权，而不改变动作表征或 VLA 主干结构。
  • 采用内层 LoRA 适配 + 外层验证选择的分离式训练流程，通过预训练审计（权重合法性/有界性/有效支持）和后训练审计（错误目标率、不安全行为率、逐组件非退化）从 8 个预声明加权设置中选出最优策略。
  • 在 UR5e 主板拆解真实平台上，对 CPU、GPU、CPU 风扇、RAM、连接器模块五类组件完成验证，取得 87/100 的成功率，显著优于 vanilla post-SFT 的 54/100。
Card 04 方法描述

方法描述

  • 基座方法：以 π_0.5-DROID 经 SFT 得到参考策略 π_θ0，作为后续所有候选适配器的共享初始化。
  • 数据结构：每条记录为 x_i = (o_i, a_{i,1:H}, m_{i,1:H}, (c_i, φ_i), t_i^act, q_i, z_i, ρ_i)，其中 ρ_i 为过程角色，t_i^act 为相位相关的交接区域。
  • 资格门控 g_i ∈ {0,1}：强制训练集归属、mask 有效性、可信来源、安全性，并排除 failure 与 excluded 角色。
  • 行权重公式：w_i(η) = g_i · clip(max(f_ρi, α_η(ρi) · exp((s_η(i) - b_str(i)) / (τ σ_str(i) + ε))), 0, w_max)，其中 s_η(i) = Σ β_k e_k(i) 为过程得分，使用中位数和 MAD 在同组件-相位-角色组内做稳健中心化。
  • 加权损失：L_PACER(θ;η) = Σ_i Σ_h w_i(η) m_{i,h} ℓ_act(θ;i,h) / max(Σ_i Σ_h w_i(η) m_{i,h}, ε)，采用 minibatch 归一化保持不同设置间的损失尺度可比。
  • 候选选择：每个候选 η 用验证集预测的 chunk 打分（几何、stop/handoff 正确性、与干净/纠正 chunk 对齐、相对 π_θ0 非退化），经 blocker B_j(η) 过滤错误目标与不安全行为，最终以组件均衡的 J_val(η) 排名选优（Eq. 6）。
  • 数据隔离：case group（同一案例的 rollout + 纠正 + 补充演示）整体划分到训练或验证，测试集 T_test 场景与 D_demo、D 完全不相交。
Card 05 数据集与资源

数据集与资源

  • 初始演示数据集 D_demo：710 条遥操作轨迹，覆盖五类组件。
  • 后训练数据集 D：参考策略部署后每类组件收集 70 次自主 rollout，成功率分别为 CPU 4、GPU 31、CPU 风扇 11、RAM 7、连接器模块 2；配合即时的算子纠正与覆盖协议下的补充干净演示。

Card 06 评估与结果

评估与结果

  • 评估环境：真实 UR5e 主板拆解，五大组件（RAM、Connector、CPU、GPU、CPU fan）。
  • 基准设置：每类组件 2 个测试场景配置（1 个接近训练分布、1 个 OOD），每配置 10 次试验，共 20 次/组件、100 次/方法。
  • 成功判据：算子判定固定下游技能可从到达状态可靠执行，且试验在到达有效交接状态前没有超时、不安全中止或人为干预；指标仅评估 planner approach-and-handoff，在下游技能执行前结束。
  • 整体成功率（Table 1）：

- PACER selected：87/100（95% Wilson CI [79.0, 92.2]），验证分 J_val = 0.7707

- Fixed geometry：79/100（J_val = 0.7699）

- Uniform all-eligible：64/100

- Vanilla post-SFT：54/100（[44.3, 63.4]）

- Clean only：24/100，Outcome only：11/100，Initial SFT π_θ0：12/100，Correction only：0/100

  • 逐组件（n=20）：PACER 在 RAM 19、Connector 13、CPU 15、GPU 20、CPU fan 20，均不低于 Fixed geometry（18/11/12/20/18）。
  • 选中的加权设置为 terminal_stop_heavy，强调终末区域与 stop 信号证据；在 8 个候选的单独硬件对比中也取得最高成功率。
  • 受控 OOD 对比（Table 2）：PACER 在 mild 配置 43/50、strong 配置 29/50，整体 72/100；相较 Fixed geometry / RW-like / Uniform / Role only 分别领先 +21 / +21 / +24 / +33 个百分点。
  • 数据消融：移除 clean 数据整体降至 35/100（PACER 领先 +37），移除 correction 数据降至 13/100（领先 +59），移除 outcome 信息降至 50/100，说明纠正与结果标签对性能至关重要。
