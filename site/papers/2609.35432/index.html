Card 03 核心贡献

核心贡献

  • 形式化 Coding Agents for the Physical World 与 Physical Coding，提出 Code as World（对象、关系、观测、状态、约束、进度谓词）与 Code as Policy（规划、工具调用、验证、恢复、执行）这一耦合的可执行接口
  • 构建 HexaAnything 物理编码智能体，将语言模型、状态观测、验证器与动作工具整合进统一的物理执行闭环
  • 提出以验证器为中心的 物理自演化框架，定义四个耦合演化目标（Harness、模型与算法、数据与环境、本体与算力）以及包含 Specify/Execute/Verify/Diagnose/Propose/Evaluate/Commit 七步的自演化循环
  • 在 RoboCasa365 长程操作任务上给出 Harness、数据、模型与工具层面的改进证据，并在 PhyBench 模拟实验室中展示同一 Harness 自主完成科学实验
  • 在 PhyBench 与真实双臂 AgileX 机器人上验证自主执行物理实验与大部分桌面任务，常快于已发表结果
Card 04 方法描述

方法描述

  • 采用双可执行产物：世界程序 W 记录任务相关世界状态与进度谓词，策略程序 P 以类型化节点组织观测、动作、验证、分支、循环与恢复
  • Harness 被形式化为 H_t = (O_t, T_t, V_t, R_t, M_t, Γ_t)，包含观测接口、工具注册表、验证器、恢复算子、记忆与执行契约/权限/预算/安全门
  • 环境策略按 n_t = π_θ(z, W_t, P_t, O_≤t, M_t) 生成类型化策略步骤，再由 Dispatch(n_t, T_t) 调用工具执行
  • 关键创新：验证器独立于提出动作的模型，返回类型化裁决（pass、fail、insufficient evidence、blocked、safety stop），所有观测携带来源（provenance），任务成功仅在新鲜证据上满足目标谓词时成立
  • 世界程序以 VCode 方式从图像写出（不读取模拟器特权状态），适配真实机器人仅有图像、本体感觉与工具输出的条件
  • VLA/WAM 被降级为一个可调用的动作工具，任务分解、完成判定与恢复由外层程序负责
  • 自演化循环采用 generate–evaluate–select 模式，演化单元为版本化产物包 a_v = (W_v, P_v, H_v, D_v, M_v, E_v)，候选仅在独立留出集上改进且不违反接口契约时才被接纳，否则回滚
  • 提出 E0–E4 证据阶梯（可运行 / oracle 可完成 / 可区分策略 / 训练新检查点有效 / 迁移到真机或分布偏移）以区分 Harness 改进与真正的模型改进

Card 06 评估与结果

评估与结果

  • 评估覆盖三类环境：长程操作仿真（RoboCasa365）、模拟科学实验（PhyBench）、真实双臂机器人部署
  • 关键指标：任务成功率（含 Composite-Unseen 与整体）；物理实验则以估计量精度（弹簧刚度 k、重力加速度 g、简正模频率）衡量
  • RoboCasa365：HexaAnything 在 Composite-Unseen 与整体成功率上均优于 XR-1 VLA，表明显式工作流、验证与恢复优于直接策略映射
  • 模型演化：用 Harness 轨迹训练的 HexaModel 在所有数据划分上超过其基座模型，说明代码轨迹可内化物理执行能力
  • 指令消融：QwenGR00T 在 LIBERO 上屏蔽指令后仍达 92.3%，仅比指令条件版本 96.2% 低至多 6.0 个百分点，且同一策略在空指令下仍完成"拿起字母汤放进篮子"，证明 VLA 很大程度在拟合场景到轨迹的映射
  • 真实机器人：在 AgileX 双臂平台与 PhyBench 上自主完成物理实验和多数桌面任务，常快于已发表结果；工具演化可在真机上由编程智能体在回合间写入、验证并冻结
  • 局限性：报告仅覆盖 Harness 与工具演化及首次"数据到模型"更新，四个演化目标的协同共演化、权重内化、架构/语言/表征/任务的自主重设计仍属未来工作，多数实验在仿真中完成
