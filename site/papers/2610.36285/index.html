Card 03 核心贡献

核心贡献

  • 提出面向冻结导航策略的命令持续性调度框架，将“是否复用上一条命令”形式化为一个可学习的事件触发决策，且该框架不改变下游执行接口。
  • 设计上下文条件化的轻量多模态预测器，融合时序观测、语言指令、执行历史与缓存的 VLA 置信度，并加入显式资格检查（eligibility check），只对前向类命令且连续复用次数小于 8 的边界启用预测。
  • 完成 R2R-CE 训练 → RxR-CE val-unseen 零目标域调优的跨数据集评估，在保持导航性能基本不变的同时降低 VLA 调用与估计推理时间。
  • 与 FlashTrigger、SP-VLA 及自建诊断基线（Free Rule、Full Gate）系统对比，揭示效率–一致性权衡，并强调必须计入调度开销。
Card 04 方法描述

方法描述

  • 调度粒度：ASPEN 工作在高层命令边界（不是仿真器单步）；边界 \(t+1\) 处，前一命令 \(a_t\) 已执行完毕，观测 \(o_{t+1}\) 可用。
  • 资格检查：\(e_{t+1}=\mathbf{1}\{a_t\in\mathcal{A}_{\mathrm{fwd}} \land r_t<8\}\)，只有合格边界才计算持续性分数；不合格边界直接调用 NaVILA。
  • 触发规则：若 \(e_{t+1}=1\) 且 \(q_{t+1}=p_\theta(a_t\mid o_{t+1},h_t)\ge\tau\)，复用 \(a_t\)；否则调用 VLA 得到 \(a^{\mathrm{NaVILA}}_{t+1}\)，仅在刷新时生成参考命令，不用于验证复用。
  • 视觉编码：冻结 SigLIP 编码每回合首帧视图与最近两个历史决策点视图，每个视图池化为 9×9 token 网格并投影到宽度 256。
  • 语言编码：冻结 Llama-3 每回合仅编码一次指令文本，最终隐状态投影到宽度 256，作为交叉注意力的 key/value。
  • 历史状态向量：编码已执行命令、幅度、步数、重复标志、回合进度特征与缓存的 NaVILA 置信度；借鉴 DINO-WM，状态向量加到对应视觉 token 上，并作为独立 state token 输入。
  • 预测网络：2 层宽度 256、4 个注意力头的 Transformer，对视觉与状态 token 做因果自注意力 + 指令交叉注意力 + 前馈；状态输出 \(h_t\) 通过注意力池化查询当前视图，当前视图的 81 个 token 不经过 Transformer；末层 MLP 输出 NaVILA 10 类规范命令上的分布。
  • 训练与阈值标定：冻结 NaVILA rollout 上做十类下一命令交叉熵，并加入错误复用后的补充样本；AdamW，学习率 5×10⁻⁴，batch size 32，3 个随机种子，最多 100 epoch，15 epoch 早停；用校准集做确定性回放，在经验分歧率 ≤10% 约束下最大化调用节省，得 τ = 0.9418（取中位种子）。
Card 05 数据集与资源

数据集与资源

  • 训练数据：R2R-CE 训练集划分，按建筑分为 42/6/13 栋、对应 2,536/405/1,685 个 episode 的训练/检查点选择/校准三部分（互不重叠）。
  • 评估数据：RxR-CE val-unseen 共 1,223 个 episode，无目标域训练或调参。
  • 基座模型：冻结的 NaVILA 作为被调度的导航 VLA 策略。
  • 辅助编码器：冻结 SigLIP（视觉）与冻结 Llama-3（语言）。
  • 预测器规模：宽度 256、2 层、4 头的轻量 Transformer + MLP，明显小于基座 VLA。
  • 硬件资源：单块 NVIDIA RTX PRO 6000 Blackwell GPU，在 20 个 profiling episode 上采集 241 次 ASPEN 门控调用用于单元代价测量。
  • 开销构成：ASPEN 门控估计代价 19.45 ms（图像解码、预处理、视觉编码、池化、预测、通信的逐项中位数之和），其中预测器本身仅 1.5 ms，共享 SigLIP 视觉编码 10.5 ms。
Card 06 评估与结果

评估与结果

  • 评估环境：RxR-CE val-unseen 跨数据集设定，全部方法使用同一套估计流程（含调度开销与每回合一次指令编码）。
  • 导航指标：SR（成功率）、OS（oracle 成功）、nDTW（归一化动态时间规整）、NE（导航误差）。
  • 效率指标：每回合 VLA 调用次数、每回合估计推理时间；另有精确动作序列一致率（与基线 NaVILA 完整执行序列相同的回合占比）。
  • 主结果：ASPEN 将 VLA 调用降至 68.7 次/回合（−9.5%）、估计推理时间降至 38.2 s（−8.1%），SR 53.1、OS 59.8、nDTW 63.2、NE 5.95（基线为 53.0 / 59.9 / 63.3 / 5.93），SR 与基线持平，其余指标略有下降但不显著；92.1% 回合与基线动作序列完全一致。
  • 对比 FlashTrigger：ASPEN 每回合少 3.3 次调用，但一致率由 97.5% 降至 92.1%，属于效率–一致性权衡，并非导航性能提升。
  • 对比 SP-VLA：估计时间接近（38.2 s 对 38.0 s），但 SP-VLA 成功率跌至 42.7%、一致率仅 7.3%。
  • 诊断基线：Free Rule 省得最多（−19.6% 调用/时间），但 SR 仅 49.1%、一致率 7.1%；Full Gate 调用降 11.7% 但时间仅降 3.3%，说明不单独计入调度开销会高估收益。
  • 定性案例：图 2 显示某回合调用从 53 降至 47（11%）、估计时间从 29.0 s 降至 26.4 s（9%）且轨迹保持一致；图 3 显示在需要右转的关键边界 ASPEN 正确触发刷新，而导航适配版 SP-VLA 继续直行并最终失败。
  • 局限性：所报为估计推理成本，并非实测端到端运行时间；源域选择的阈值不提供目标域分歧保证；作者将把迁移到其他导航 VLA 以及在真实机器人上测量时延与能耗列为未来工作。
