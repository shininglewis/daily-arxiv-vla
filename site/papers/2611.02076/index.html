研究单位

  • 韩国科学技术院（KAIST）
  • 作者：Seungjun Yu、Jiho Choi、Inha Kang、Hojun Choi、Seungwook Kim、Hyunjung Shim（†通讯作者）
Card 02 论文概述

论文概述

  • 论文研究扩散式驾驶 VLA（Diffusion Driving VLA）模型的推理效率问题：这类模型在每个去噪阶段都要重复执行主干网络，造成严重推理延迟。
  • 作者系统分析了轨迹信息在网络深度与解码进度上的可读出性，发现并非所有场景都需要相同的解码计算量。
  • 目标是设计一种按场景自适应分配读出层与解码预算的框架，在保持或提升规划质量的同时大幅降低推理开销。
Card 03 核心贡献

核心贡献

  • 系统分析轨迹读出在网络深度与解码进度上的表现，揭示了 Depth–Decoding Dissociation（深度—解码解耦）现象：后层表示在首次前向扫掠后即可支持高质量轨迹读出，而早层表示更依赖后续去噪。
  • 发现场景级异质性：最优读出层与最优停止解码阶段因场景而异（仅约 55% 场景以 L25 为最优层，约 61% 场景在 s=1 即达最优）。
  • 提出场景自适应读出 MoE（Scene-Adaptive Readout MoE），对后层稳定读出带内各层的轨迹预测进行场景条件加权融合。
  • 提出场景自适应解码（Scene-Adaptive Decoding），仅对预测有收益的场景启动原生解码回退，并支持在中间阶段提前停止。
  • 在两种扩散驾驶 VLA 与两个数据集上验证：RFS 最高提升 0.56，端到端推理最高加速 6.0×。
Card 04 方法描述

方法描述

  • 早期轨迹读出：冻结扩散 VLA 主干，仅做一次前向扫掠，取轨迹 token 位置在层 $\ell$ 的隐状态，并结合首轮 argmax 得到的 one-pass draft $a(x)$，由层特定读出头预测连续轨迹。
  • 稳定读出带：分析发现 L21–L29 构成性能平台，故定义读出带 $\mathcal{B}=\{21,\dots,29\}$，每层配一个读出头与隐空间编辑器（latent editor），做 $R=12$ 步残差式隐状态修正（不产生额外主干前向）。
  • 场景条件 MoE 门控：将轨迹槽与视觉 token 的均值池化特征，与自车历史、导航指令、one-pass draft、各层候选轨迹及其偏差拼接成场景表示 $u(x)$，经 softmax 门控 $g_\psi$ 输出层间混合权重并加权融合候选轨迹。
  • 辅助参考分支：固定参考层 $\ell^{\star}=27$ 的独立读出分支用于降低方差，最终草案为 $\hat\tau_{\text{read}}=(1-\beta)\hat\tau_{\text{moe}}+\beta\hat\tau_{\text{aux}}$。
  • 自适应解码回退：学习式解码门 $g_\omega$ 以读出置信度、专家分歧、导航上下文等为输入，超过阈值 $\lambda$ 才进入回退解码；回退中使用各阶段轻量探针 $\mathcal{R}^{(s)}$，以未来终点位移一致性（阈值 $\varepsilon$）确定最早可停止阶段。
  • 三路由结果：早期直接返回读出轨迹 / 中途若干阶段后停止（与阶段预测取平均）/ 完成原生解码（与原生轨迹取平均）。
Card 05 数据集与资源

数据集与资源

  • 数据集：Waymo End-to-End（WOD-E2E） 与 nuScenes。
  • 评测骨干模型：dVLM-AD（掩码扩散）与 Fast-dDrive（Block Diffusion）两种扩散驾驶 VLA，主干均保持冻结，仅训练读出头、隐编辑器、门控与阶段探针。
  • 关键超参：隐空间精修步数 $R=12$，读出带 $\mathcal{B}=\{21,\dots,29\}$，参考层 $\ell^{\star}=27$。
  • 延迟测量：单张 NVIDIA A6000，batch size 为 1，单位 ms/scene；具体训练硬件与超参细节在附录（正文未给出具体参数量）。
Card 06 评估与结果

评估与结果

  • 评估基准：Waymo E2E 验证/测试集与 nuScenes 验证集；指标为 RFS（人类评分对齐的规划质量）、ADE@3s / ADE@5s、nuScenes 的 L2@1/2/3s，以及端到端延迟。
  • dVLM-AD：RFS 验证集 7.187→7.745（+0.558），测试集 7.486→7.557（+0.071）；测试 ADE@3s 1.337→1.294，ADE@5s 3.241→3.130；延迟 31,385→5,208 ms/scene（约 6.0× 加速）。
  • Fast-dDrive：RFS 验证集 7.911→8.121（+0.210），测试集 7.823→7.881（+0.058）；测试 ADE@3s 1.254→1.196，ADE@5s 2.907→2.681；延迟 3,146→1,135 ms/scene（约 2.8× 加速）。
  • nuScenes：平均 L2 由 0.41→0.39（dVLM-AD）、0.32→0.29（Fast-dDrive），表明方法不局限于单一数据集与单一扩散架构。
  • 消融：仅早期读出已把 RFS 提到 7.594 / 8.025 且延迟大幅下降；加入场景自适应 MoE 进一步提到 7.632 / 8.116（延迟开销很小）；再加自适应解码达到 7.745 / 8.121，其中 dVLM-AD 延迟从 2,490 升至 5,208 ms（仍远低于原生 31,385 ms），Fast-dDrive 仅从 1,058 升至 1,135 ms。
