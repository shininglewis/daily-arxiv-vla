Card 03 核心贡献

核心贡献

  • 提出分解论证：在同一固定策略下对比端到端与 oracle 的受控差距，定位 VLA 记忆任务难点在“记忆→接地子目标”阶段。
  • 提出 Gamma：一个接地多智能体记忆系统（SAM-3 检测工具 + VLM 写入者 + 只追加文本记忆库 + VLM 推理者），用可验证的符号记忆替代不透明的关键帧选择。
  • 提出 propose–verify（提议–验证）机制：所有智能体声明（事件、进度、接地坐标）都必须通过机械视觉证据检查，可被 admit / defer / correct / reject，训练语料构建与部署阶段使用同一契约。
  • 在 RoboMME 上以固定策略取得非特权方法的最优记忆任务性能，并原样契约迁移到第二个基准 RoboMemArena。
  • 提出 tick 级诊断协议，可将闭环失败归因到具体记忆缺陷，实现可定位、可修复的分析。
Card 04 方法描述

方法描述

  • 检测器工具：使用 SAM-3 配合按类别调优的文本提示，逐帧输出 {name⟨x,y⟩} 形式的检测串，训练与部署使用完全相同的提示、阈值和后处理。
  • Agent-1 记忆写入者：一个微调 VLM，每个 replan tick 运行一次，从窗口采样帧、检测结果、已有记忆和上一子目标中，提炼出至多一条“身份–动态”对（identity–dynamics）的接地文本行 m_k = (ι_k, δ_k)，无新事实则输出 none。
  • 文本记忆库：只追加（append-only）列表 M_k = M_{k-1} ⊕ m_k，永不重写或摘要；保证信息不丢失、每条事实可核查、数百步压缩为少量行。
  • Agent-2 推理者：仅读取指令与记忆库（完全不看像素），按 oracle 的节奏逐字输出下一接地子目标 ĝ_k = A_2(I, M_k)；只能引用记忆中已有坐标，否则回退为“hold and observe the scene”。
  • 执行器：固定不变的子目标条件策略 π_0.5，以 oracle 行相同权重执行 a = π_0.5(o_Hk, ĝ_k)，从不基于本系统输出再训练。
  • 训练目标构建：三条契约——① 事件行来自经过验证的追踪器（覆盖事件、容器移动链、高亮出现、逐笔演示记录）；② 证据门控，行只能在其自身窗口帧包含证据时发出；③ 可知性约束，所有坐标必须在写入者可见输入中可找到，否则降级为无坐标形式。
  • 两阶段训练：写入者先在带真值记忆库的语料上微调；再在训练集上 rollout，推理者在写入者产生的预测记忆库 + oracle 子目标上微调，使训练分布与部署分布一致。
Card 05 数据集与资源

数据集与资源

  • RoboMME：16 个记忆操作任务（计数、顺序、交换、演示路线、延迟揭示等），使用留出测试 episode。
  • RoboMemArena：第二个基准，26 个长时程厨房任务，4 个记忆族，使用留出布局。
  • 基础模型：写入者与推理者共享 Qwen3.5-9B 作为底座，使用 LoRA 适配器；另训练一对 Qwen3.5-0.8B 智能体作为规模对照。
  • 检测器：SAM-3（facebook/sam3），开箱即用、从不微调。
  • 评估规模：闭环每任务每服务种子 30 episode，发布的 9B 配置使用 3 个服务种子、单一智能体 checkpoint；基线/oracle 行为 RoboMME 官方报告值（50 episodes、3 checkpoints、3 seeds）。训练资源（GPU/TPU 具体型号）在原文可见部分未明确给出。
Card 06 评估与结果

评估与结果

  • 主要指标：各任务环境谓词下的 episode 成功率（%）与 16 任务平均成功率。
  • 主结果：Gamma 平均成功率 66.0%，比最佳非特权基线 FrameSamp+Modul（44.5%）高 +21.5，达到特权 GroundSG oracle（84.1%）的 78.5%。
  • 任务级表现：在 16 个任务中的 9 个取得非特权最优；在 PickXtimes、PatternLock、RouteStick 上追平 oracle 上限（PL 98.9、RS 56.7）。
  • 增益集中区：在身份绑定类（shuffle / reveal）任务上近乎翻倍——VUS 75.6 vs 38.0、VRP 65.6 vs 30.4、VPO 66.7 vs 36.0；按压计数（BU 84.4）与路线追踪任务领先。
  • 规模对照：0.8B 智能体配置平均 57.4%，仍显著优于全部非特权基线。
  • 机制消融（9B）：去掉 defer 按压验证门导致按压任务崩溃（BU 84→57，BUS 36→13）；去掉 reject 使路线任务直接失效（PL 99→3，RS 57→7）；去掉 correct 影响最小（绑定任务降 4–7 点）；完全去掉 harness 平均降至约 55.1%。
  • 迁移性：契约不变地迁移到 RoboMemArena 进行评估，作为第二个基准验证泛化性。
